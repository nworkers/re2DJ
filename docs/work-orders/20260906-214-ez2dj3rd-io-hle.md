# 작업 지시서: ez2dj3rd I/O HLE 연결

## 한국어

관련 설계: [ez2dj3rd I/O HLE 연결 설계](../design/20260906-214-ez2dj3rd-io-hle.md)

### 목표

`ez2dj3rd --io-config <path>`에서 설정이 무시되지 않도록 공용 keyboard-to-I/O-board HLE를 3rd CHD 프로파일에 연결합니다.

### 작업 항목

1. Target profile 정책에 helper RVA 미확정 fallback 필드를 추가합니다.
2. Windows original-process backend와 launcher argument에 fallback 정책을 전달합니다.
3. debugger trap과 injected runtime에서 지원 포트와 byte I/O opcode만 처리합니다.
4. 3rd profile의 기본 실행 인자와 profile/product-loader 테스트를 갱신합니다.
5. 실행 로그와 빌드·테스트 결과를 작업 로그 및 3rd 분석 문서에 기록합니다.

### 제외 범위

- 2nd·4th helper RVA를 3rd에 복사하는 것
- 3rd Hardlock response, seed, ID, module address 추정
- 실제 cabinet 배선이나 lamp 의미 확정
- 원본 CHD·실행 파일 저장소 추가

### 완료 조건

- `--io-config`가 3rd에서 더 이상 무시되지 않습니다.
- 지원되지 않는 포트와 opcode는 fallback이 삼키지 않습니다.
- Windows x86 build, unit test, product-loader probe가 통과합니다.
- 실행 결과에서 fallback이 미확정 helper 주소를 의미하지 않는다는 점이 문서화됩니다.

## English

Related design: [ez2dj3rd I/O HLE Connection Design](../design/20260906-214-ez2dj3rd-io-hle.md)

### Objective

Connect the shared keyboard-to-I/O-board HLE to the 3rd CHD profile so `ez2dj3rd --io-config <path>` is no longer ignored.

### Work items

1. Add a target-profile fallback field for the unresolved helper RVA.
2. Pass the fallback policy through the Windows original-process backend and launcher arguments.
3. Handle only supported ports and byte-I/O opcodes in the debugger trap and injected runtime.
4. Update the 3rd profile defaults and profile/product-loader tests.
5. Record run evidence and build/test results in the work log and 3rd analysis.

### Out of scope

- Copying 2nd or 4th helper RVAs into the 3rd profile
- Guessing the 3rd Hardlock response, seeds, IDs, or module address
- Confirming physical cabinet wiring or lamp meanings
- Adding original CHD or executable assets to the repository

### Completion criteria

- `--io-config` is no longer ignored for 3rd.
- The fallback does not consume unsupported ports or opcodes.
- The Windows x86 build, unit test, and product-loader probe pass.
- Documentation makes clear that fallback handling is not a confirmed helper address.
