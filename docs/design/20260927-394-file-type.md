# 작업 394 설계 — 파일 handle의 GetFileType / Task 394 design — GetFileType for file handles

선행: [작업 393 설계](20260927-393-current-directory.md)

## 배경 / Background

작업 393 뒤 Linux 실행은 CRT가 `aw-logo.ezw`를 여는 과정에서 멈췄다. CRT(`fopen` 계열)는 `CreateFileA`로 연 handle의 종류를 `GetFileType`으로 묻는다. 그런데 이 export는 `GuestFiles`가 생기기 전에 만들어져, 장치가 아닌 handle은 모두 모르는 handle로 답했다(0, `ERROR_INVALID_HANDLE`). CRT는 handle을 닫고 실패를 돌려주었고, 게임은 결과를 확인하지 않고 쓰다가 SIGSEGV로 멈췄다.

*After Task 393 a Linux run stopped as the CRT opened `aw-logo.ezw`. The CRT (the `fopen` family) asks `GetFileType` for the type of a handle `CreateFileA` returned. That export predated `GuestFiles` and answered every non-device handle as unknown (0, `ERROR_INVALID_HANDLE`). The CRT closed the handle and failed, and the game used the result unchecked and stopped with SIGSEGV.*

### 측정 / Measurements

32비트 PowerShell에서 P/Invoke로 측정했다(Windows 11, 3바이트 파일).

| handle | 결과 / Result | last error |
| --- | --- | --- |
| 읽기·쓰기·access 0으로 연 파일 / *a file opened for read, write, or no access* | 1 (`FILE_TYPE_DISK`) | 그대로 / *unchanged* |
| 닫은 handle / *a closed handle* | 0 | 6 |
| NULL, `INVALID_HANDLE_VALUE`, `0x1234` | 0 | 6 |

## 결정 / Decisions

1. **파일 handle.** `GuestFiles`에 열려 있는 handle은 `FILE_TYPE_DISK`이고, last error는 그대로 둔다. CHD에서 읽는 파일과 overlay의 host 파일 모두 해당한다. / ***File handles.** A handle open in `GuestFiles` is `FILE_TYPE_DISK` and leaves the last error alone, whether the file reads from the CHD or from a host overlay file.*
2. **나머지.** 모르는 handle은 지금처럼 `FILE_TYPE_UNKNOWN`과 `ERROR_INVALID_HANDLE`이다. 장치 handle은 여전히 모델 밖이다. / ***The rest.** An unknown handle stays `FILE_TYPE_UNKNOWN` with `ERROR_INVALID_HANDLE`, and a device handle is still unmodelled.*

## 범위 밖 / Out of scope

- 표준 입출력 handle, pipe, 문자 장치의 종류. / *The types of standard handles, pipes, and character devices.*
- 진단용 호출 한도(32,768번). 이번 실행이 로고 장면을 그리다 멈추는 곳이다. 제품 실행은 창을 닫을 때까지 돌아야 하므로 다음 작업에서 다룬다. / *The diagnostic call limit (32,768 calls), where the run now stops while drawing the logo scene. A product run has to go on until its window is closed, which is the next task.*
