# 작업 409 설계 — Sleep / Task 409 design — Sleep

선행: [작업 408 설계](20260927-408-display-settings.md)

## 배경 / Background

작업 408 뒤 Linux의 EZ2DJ 1st는 화면 모드를 요청한 다음 `kernel32!Sleep(3000)`에서 멈췄다. Windows 제품의 `Sleep`은 진짜 `Sleep`이다. 제품은 가로채서 대기 시간을 기록할 뿐이다(`Re2djWaitSleep`).

*After Task 408, EZ2DJ 1st on Linux stopped at `kernel32!Sleep(3000)` after asking for its display mode. The Windows product's `Sleep` is the real one, wrapped only to account for the waits (`Re2djWaitSleep`).*

## 결정 / Decisions

1. `ImportCallServices::WaitMilliseconds`를 더한다. host가 guest 스레드를 그만큼 재운다. Linux diagnostic은 `CLOCK_MONOTONIC`의 `clock_nanosleep`으로 재우고, 신호로 깨면 남은 시간만큼 다시 잔다.
   *`ImportCallServices::WaitMilliseconds` lets the host put the guest thread to sleep; the Linux diagnostic uses `clock_nanosleep` on `CLOCK_MONOTONIC`, resuming after a signal for the time left.*
2. kernel32 `Sleep`: `Sleep(0)`은 스레드가 하나뿐이라 바로 돌아온다. 그 밖의 값은 host가 기다린다. last error는 그대로다. `INFINITE`는 유일한 guest 스레드를 영원히 막으므로 멈춘다.
   *kernel32 `Sleep`: `Sleep(0)` returns at once, there being one thread; other values wait on the host; the last error is left alone. `INFINITE` would block the only guest thread forever and stops.*
3. 기다리는 동안에는 host 창 이벤트를 처리하지 않는다. 이 호출은 host 창이 열리기 전에 나오고, 창은 매 `Present`마다 이벤트를 비운다.
   *Host window events are not pumped during the wait: this call comes before the host window opens, and the window drains its events at every `Present`.*
