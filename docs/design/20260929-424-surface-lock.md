# 작업 424 설계 — IDirectDrawSurface7::Lock / Unlock / Task 424 design — IDirectDrawSurface7::Lock and Unlock

선행: [작업 423 설계](20260929-423-software-present-pacing.md)

## 배경 / Background

사용자가 Linux에서 4th를 하다 F1을 누르자 실행이 끝났다. 로그를 보면 크래시가 아니라 미구현 import에서 멈춘 것이다. 순서는 다음과 같다.

1. 게임이 표면들을 놓고 소리를 멈춘다(장면 전환).
2. `IDirect3DDevice7::Clear` 뒤 back buffer(`ef600028`)에 `IDirectDrawSurface7::Lock(NULL, desc, DDLOCK_WAIT, NULL)`을 부른다.
3. 이 Lock에서 멈췄다(`continuation : stopped at unhandled import ddraw.dll!IDirectDrawSurface7::Lock`).

Windows DX6 facade(DX7 표면도 그대로 가져다 쓴다)에는 Lock이 있다. 하지만 그 규칙이 facade 안에만 있었다.

*When the user pressed F1 while playing 4th on Linux, the run ended. The log shows no crash but a stop at an unimplemented import:*
1. *the game releases its surfaces and stops its sounds (a scene change);*
2. *after `IDirect3DDevice7::Clear` it calls `IDirectDrawSurface7::Lock(NULL, desc, DDLOCK_WAIT, NULL)` on the back buffer (`ef600028`);*
3. *the run stopped at that Lock (`continuation : stopped at unhandled import ddraw.dll!IDirectDrawSurface7::Lock`).*

*The Windows DX6 facade, which DX7 surfaces adopt unchanged, has Lock, but its rules lived only inside the facade.*

## 결정 / Decisions

1. **Lock 규칙을 공용 core로 옮긴다.** `directx::PlanLock`이 Windows facade의 규칙을 그대로 담는다. Windows facade와 Linux 모듈이 모두 이를 쓴다.
   - 설명 구조체가 없거나 `dwSize`가 틀리거나 event를 주면 `DDERR_INVALIDPARAMS`다.
   - 픽셀이 없는 표면은 `DDERR_INVALIDOBJECT`다.
   - 비었거나 표면을 벗어나는 사각형은 `DDERR_INVALIDRECT`다.
   - 그 밖에는 GetSurfaceDesc의 설명에 `DDSD_LPSURFACE`를 더한다. 크기는 사각형(없으면 표면)의 크기이고, pitch는 표면 전체의 pitch다. 사각형 첫 픽셀의 오프셋도 준다.
   - 플래그는 보지 않는다. `DDSD_LPSURFACE` 값은 Windows에서 SDK와 대조한다.

   *The Lock rules move to the shared core. `directx::PlanLock` carries the Windows facade's rules unchanged, and both the Windows facade and the Linux module use it:*
   - *no description, a wrong `dwSize`, or an event is `DDERR_INVALIDPARAMS`;*
   - *a surface without pixels is `DDERR_INVALIDOBJECT`;*
   - *an empty rectangle, or one leaving the surface, is `DDERR_INVALIDRECT`;*
   - *otherwise it is GetSurfaceDesc's description plus `DDSD_LPSURFACE`, sized to the rectangle (or the surface), with the whole surface's pitch and the offset of the rectangle's first pixel;*
   - *the flags are ignored, and the value of `DDSD_LPSURFACE` is checked against the SDK on Windows.*
2. **Linux 모듈.** `Lock`은 guest 메모리에 있는 표면 자신의 픽셀 주소를 넘긴다. `Unlock`은 표면의 revision을 올린다. 그래서 host가 가진 사본(텍스처)은 다음에 다시 만들어진다. Windows의 `MarkSurfaceDirty`와 같은 역할이다.
   *The Linux module. `Lock` hands out the address of the surface's own pixels in guest memory, and `Unlock` bumps the surface's revision so the host copy (texture) is rebuilt next time, as Windows' `MarkSurfaceDirty` does.*
3. **렌더 타깃은 되읽지 않는다.** 두 host 모두 렌더 타깃을 Lock해도 render backend의 그림을 guest 픽셀로 되읽지 않는다. CPU로 쓴 픽셀도 화면에 올리지 않는다. 이 작업은 동작을 Windows와 같게 맞출 뿐이다. 그래서 F1 뒤 화면은 두 host 모두 검다(측정 기록 참고).
   *A render target is not read back. On both hosts, locking a render target does not read the render backend's picture back into guest pixels, and pixels written by the CPU are not put on screen. This task only brings behavior in line with Windows, so after F1 the screen is black on both hosts (see the measurements).*
