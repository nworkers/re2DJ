# 작업 386 설계 — winmm mixer / Task 386 design — the winmm mixer

선행: [작업 385 설계](20260926-385-linux-legacy-io-ports.md)

## 배경 / Background

작업 385 뒤 Linux 실행은 `winmm!mixerGetNumDevs`에서 멈췄다. Windows runtime은 mixer를 대신 처리하지 않고 host의 실제 mixer를 그대로 쓴다. 4th는 import를 보호 코드가 다시 짜기 때문에, 이름으로 IAT를 바꾸는 audio trace로는 게임의 mixer 호출이 잡히지 않았다.

그래서 이 Windows 11 host의 첫 mixer를 32비트 PowerShell로 측정했다.

- **대상 line**: 1개. speakers(`0xffff0000`)이고, source line 2개와 control 2개를 갖는다. 대상 line의 `dwSource`는 `0xFFFFFFFF`로 돌아온다.
- **source line**: CD Audio(`0x00000000`, 구성 요소 `0x1005`)와 wave out(`0x00010000`, 구성 요소 `0x1008`, 대상 유형 1).
- **control**: line마다 Mute(`0x20010002`, 0–1)와 Volume(`0x50030001`, 0–65535, 192단계)이 있다. ID는 1–6이다. Volume의 초기값은 65535다.
- **값**:
  - 범위를 벗어난 값을 쓰면 `MMSYSERR_NOERROR`를 돌려주지만 값은 바뀌지 않는다.
  - Mute를 두 채널로 읽으면 `MMSYSERR_INVALPARAM`이다. Volume은 한 채널로 읽든 두 채널로 읽든 같은 값을 준다.
- **오류**: 잘못된 장치 ID는 2, 잘못된 handle은 5, 모르는 조회 flag는 10, 작은 `cbStruct`는 11, 없는 line은 1024, 없는 control은 1025다.

*After Task 385 a Linux run stopped at `winmm!mixerGetNumDevs`. The Windows runtime does not model the mixer; it uses the host's real one. Because the 4th's protection rebuilds its imports, the audio trace that swaps IAT entries by name never caught the game's mixer calls.*

*So this Windows 11 host's first mixer was measured from 32-bit PowerShell:*

- ***Destination line:** one, the speakers (`0xffff0000`), with two source lines and two controls. The destination's `dwSource` comes back as `0xFFFFFFFF`.*
- ***Source lines:** CD Audio (`0x00000000`, component `0x1005`) and wave out (`0x00010000`, component `0x1008`, target type 1).*
- ***Controls:** each line has Mute (`0x20010002`, 0–1) and Volume (`0x50030001`, 0–65535, 192 steps), with IDs 1–6. Volumes start at 65535.*
- ***Values:***
  - *Writing a value outside the bounds returns `MMSYSERR_NOERROR` and leaves the value unchanged.*
  - *Reading Mute with two channels is `MMSYSERR_INVALPARAM`. Volume gives the same value whether read with one channel or two.*
- ***Errors:** a bad device ID is 2, a bad handle 5, an unknown query flag 10, a small `cbStruct` 11, a missing line 1024, and a missing control 1025.*

## 결정 / Decisions

1. **모델(`re2dj/hle/guest_mixer.h`).**
   - Linux mixer는 장치 하나로 모델링한다. DirectDraw facade가 모니터 하나를 두는 것과 같다.
   - line과 control 표는 측정값 그대로 두되, host의 장치 이름은 고정 이름 "re2DJ Audio"로 바꾼다.
   - `GuestProcess::mixer()`가 열린 handle과 guest가 쓴 control 값을 갖는다.
   - Windows는 계속 host mixer를 쓰므로 공용 core로 옮길 규칙이 없다. 그래서 모델은 HLE 쪽에 둔다.

   ***Model (`re2dj/hle/guest_mixer.h`):***
   - *The Linux mixer is modelled as one device, as the DirectDraw facade models one monitor.*
   - *The line and control tables keep the measured values, with the host's device name replaced by the fixed name "re2DJ Audio".*
   - *`GuestProcess::mixer()` holds the open handles and the control values the guest writes.*
   - *Windows keeps using the host mixer, so there are no rules to move into a shared core, and the model lives on the HLE side.*
2. **winmm handler.**
   - `mixerGetNumDevs`, `mixerOpen`, `mixerClose`를 구현한다.
   - `mixerGetLineInfoA`는 대상, source, line ID, 구성 요소 유형으로 찾는다.
   - `mixerGetLineControlsA`는 전체, ID, 유형으로 찾는다.
   - `mixerGetControlDetailsA`와 `mixerSetControlDetails`는 VALUE 조회만 다룬다.
   - mixer는 handle(`MIXER_OBJECTF_HMIXER`)이나 mixer ID 0으로 지정할 수 있다.
   - 측정하지 않은 형태는 불리면 멈춘다. callback으로 열기, 대상 유형 조회, 다른 객체 유형, 비표준 구조체 크기, 여러 채널 쓰기가 여기에 속한다.

   ***winmm handlers:***
   - *`mixerGetNumDevs`, `mixerOpen`, and `mixerClose` are implemented.*
   - *`mixerGetLineInfoA` looks lines up by destination, source, line ID, or component type.*
   - *`mixerGetLineControlsA` returns all controls, or one by ID or type.*
   - *`mixerGetControlDetailsA` and `mixerSetControlDetails` handle only the VALUE query.*
   - *A mixer can be named by handle (`MIXER_OBJECTF_HMIXER`) or by mixer ID 0.*
   - *Shapes that were not measured stop when called: opening with a callback, target-type queries, other object types, nonstandard structure sizes, and multi-channel writes.*
3. **소리와의 관계.** Linux 소리 출력 단계에서 wave out Volume/Mute 값을 실제 출력 이득에 연결한다.
   ***Relation to sound:** the Linux sound-output phase will connect the wave-out Volume/Mute values to the actual output gain.*
