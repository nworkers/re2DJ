# EZ2DJ 3rd IO 입력 진단 및 수정 설계

## 한국어

### 배경

Task 217에서 윈도우 모드 프라이머리 서피스 Blt 프레젠테이션이 구현되어 `ez2dj3rd`의 인트로 화면 및 사운드가 정상적으로 출력(60 FPS)되었습니다.
그러나 사용자가 `--io-config .\config\ez2dj-io.example.ini` 옵션을 지정하여 실행하였음에도 코인 투입(F5), 시작(1/2), 건반, 턴테이블, 이펙터 등의 키 입력이 게임에 전달되지 않는 현상이 확인되었습니다.

### 원인 분석

메모리 덤프(`0x00401000`~`0x00700000`) 및 역어셈블 분석을 통해 다음과 같은 복합 원인을 규명했습니다.

1. **`ParseKey`의 미지원 키(`TAB`)로 인한 입력 폴링 초기화 실패**:
   `config/ez2dj-io.example.ini`의 26행에 `p1_positive=TAB`이 지정되어 있습니다.
   그러나 `src/platform/windows/ez2dj_keyboard_input.cpp`의 `ParseKey` 함수는 `TAB` 키를 지원하지 않아 `-1`을 반환했습니다.
   이로 인해 `Ez2DjKeyboardInput::Initialize`가 `"unknown key name for turntables.p1_positive: TAB"` 에러를 반환하고 실패하여, `g_keyboard_input_state`가 `2`(에러 상태)로 전환되었습니다.
   결과적으로 런타임 수명 전체 동안 `g_keyboard_input.Poll`이 단 한 번도 호출되지 않았습니다.

2. **상대 경로 전달 시 게스트 작업 디렉터리(`TEMP/.../EZ2DJ`) 불일치**:
   사용자가 지정한 `--io-config .\config\ez2dj-io.example.ini`가 상대 경로 그대로 `EZ2DJ.EXE` 프로세스 내부의 `re2dj_injected_runtime.dll` 전역 변수로 복사되었습니다.
   CHD 타깃의 실행 디렉터리는 임시 압축 해제 경로(`%TEMP%/re2dj/chd/ez2dj3rd/EZ2DJ`)이므로, `GetPrivateProfileStringA`에 상대 경로를 전달할 경우 해당 임시 디렉터리에서 `.\config\ez2dj-io.example.ini`를 탐색하게 되어 파일을 찾지 못하고 모든 키 매핑이 기본값 `"NONE"`(0)으로 파싱됩니다.

3. **`ez2dj3rd` 대상 Legacy I/O Helper RVA 미확정 상태**:
   `src/target/target_profile.cpp`에서 `ez2dj3rd`는 helper RVA가 미확정 상태(`legacy_io_in_byte_rva = 0`, `legacy_io_out_byte_rva = 0`, `legacy_io_port_range_fallback = true`)로 설정되어 있었습니다.
   메모리 역어셈블 분석 결과, 3rd의 I/O 헬퍼가 1st/2nd/4th와 동일한 구조로 존재함이 확인되었습니다:
   - `in al, dx` 헬퍼: `0x004A9880` (실제 `in al, dx` 명령어 RVA: `0x000A9887`)
   - `out dx, al` 헬퍼: `0x004A98B0` (실제 `out dx, al` 명령어 RVA: `0x000A98BB`)
   - 입력 포트: `0x101`(1P 스타트/이펙터/서비스/테스트), `0x102`(1P 건반/페달), `0x106`(2P 건반/페달), `0x103`(1P 턴테이블), `0x104`(2P 턴테이블), `0x105`(코인 카운터)
   - 출력 포트: `0x100`, `0x101`, `0x102`, `0x103` (조명 제어)

   `src/platform/windows/ez2dj_keyboard_input.cpp`의 `ParseKey`에 `TAB`(`VK_TAB`), `ESCAPE`/`ESC`, `LSHIFT`, `RSHIFT`, `SHIFT`, `LCONTROL`/`LCTRL`, `RCONTROL`/`RCTRL`, `CONTROL`/`CTRL`, `LMENU`/`LALT`, `RMENU`/`RALT`, `ALT`, `BACKSPACE`/`BACK`, `CAPITAL`/`CAPSLOCK`/`CAPS`, `INSERT`, `DELETE`/`DEL`, `HOME`, `END`, `PAGEUP`/`PGUP`, `PAGEDOWN`/`PGDN` 등을 추가합니다.

## English

### Background

In Task 217, the windowed primary surface Blt presentation was implemented, allowing `ez2dj3rd`'s intro visuals and sound to play properly at 60 FPS.
However, even when the user executed with `--io-config .\config\ez2dj-io.example.ini`, inputs such as coin insertion (F5), start (1/2), keys, turntables, and effectors were not functioning in the game.

### Root Cause Analysis

Through memory dump (`0x00401000`–`0x00700000`) and disassembly analysis, multiple combined root causes were identified:

1. **Keyboard input polling initialization failure due to unsupported key (`TAB`) in `ParseKey`**:
   Line 26 of `config/ez2dj-io.example.ini` specifies `p1_positive=TAB`.
   However, `ParseKey` in `src/platform/windows/ez2dj_keyboard_input.cpp` did not support `TAB`, returning `-1`.
   This caused `Ez2DjKeyboardInput::Initialize` to fail with `"unknown key name for turntables.p1_positive: TAB"`, setting `g_keyboard_input_state` to `2` (error state).
   As a result, `g_keyboard_input.Poll` was never called throughout the entire runtime lifetime.

2. **Guest working directory (`TEMP/.../EZ2DJ`) mismatch when passing relative paths**:
   The user-specified relative path `--io-config .\config\ez2dj-io.example.ini` was written verbatim into `re2dj_injected_runtime.dll`'s global buffer inside `EZ2DJ.EXE`.
   Because the execution working directory of a CHD target is its temporary unpack path (`%TEMP%/re2dj/chd/ez2dj3rd/EZ2DJ`), `GetPrivateProfileStringA` resolved the relative path against that temp folder, failed to find the file, and defaulted all key mappings to `"NONE"` (0).

3. **Unconfirmed Legacy I/O Helper RVAs for `ez2dj3rd`**:
   In `src/target/target_profile.cpp`, `ez2dj3rd` had unconfirmed helper RVAs (`legacy_io_in_byte_rva = 0`, `legacy_io_out_byte_rva = 0`, `legacy_io_port_range_fallback = true`).
   Memory disassembly confirmed that 3rd's I/O helper structure matches 1st/2nd/4th:
   - `in al, dx` helper: `0x004A9880` (instruction RVA: `0x000A9887`)
   - `out dx, al` helper: `0x004A98B0` (instruction RVA: `0x000A98BB`)
   - Input ports: `0x101` (1P start/effectors/service/test), `0x102` (1P keys/pedal), `0x106` (2P keys/pedal), `0x103` (1P turntable), `0x104` (2P turntable), `0x105` (coin counter)
   - Output ports: `0x100`, `0x101`, `0x102`, `0x103` (light control)

### Proposed Changes

1. **Expand `ParseKey` Key Mappings**:
   Add `TAB` (`VK_TAB`), `ESCAPE`/`ESC`, `LSHIFT`, `RSHIFT`, `SHIFT`, `LCONTROL`/`LCTRL`, `RCONTROL`/`RCTRL`, `CONTROL`/`CTRL`, `LMENU`/`LALT`, `RMENU`/`RALT`, `ALT`, `BACKSPACE`/`BACK`, `CAPITAL`/`CAPSLOCK`/`CAPS`, `INSERT`, `DELETE`/`DEL`, `HOME`, `END`, `PAGEUP`/`PGUP`, `PAGEDOWN`/`PGDN`, etc. to `ParseKey` in `src/platform/windows/ez2dj_keyboard_input.cpp`.
2. **Canonicalize `io_config` to Absolute Path**:
   In host CLI (`src/host/cli/main.cpp`), backend (`src/platform/windows/original_process_backend.cpp`), and launcher probe (`src/tools/windows_x86_launcher_probe/main.cpp`), convert `io_config` paths to `std::filesystem::absolute` to ensure reliable loading regardless of the guest process working directory.
3. **Confirm and Apply `ez2dj3rd` I/O Helper RVAs**:
   Update `src/target/target_profile.cpp` for `ez2dj3rd` with confirmed RVAs: `legacy_io_in_byte_rva = 0x000a9887`, `legacy_io_out_byte_rva = 0x000a98bb`, and disable `legacy_io_port_range_fallback`.
4. **Update Unit Tests and Add New Tests**:
   Update `tests/unit/target_profile_test.cpp` and `src/tools/windows_product_loader_probe/main.cpp`, and add unit tests validating key parsing and configuration loading in `Ez2DjKeyboardInput`.
