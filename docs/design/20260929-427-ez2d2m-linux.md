# 작업 427 설계 — Linux에서 EZ2Dancer 2nd MOVE 실행 / Task 427 design — running EZ2Dancer 2nd MOVE on Linux

선행: [작업 426 설계](20260929-426-palettized-dib.md)

## 배경 / Background

사용자가 Linux에서 ez2d2m을 실행하자 보호 envelope이 원본 import 표를 다시 만들다가 `GetProcAddress(kernel32, "WaitCommEvent")`의 NULL에서 멈췄다. 이 경계를 고친 뒤에도 차례로 세 경계가 더 나왔다.

1. `CreateWindowExA`의 `WS_BORDER`
2. 처리되지 않은 게스트 예외(`UnhandledExceptionFilter`)
3. IO 보드 입력 명령(`in ax, dx`)

*When the user ran ez2d2m on Linux, the protection envelope stopped while rebuilding the original import table, at a NULL from `GetProcAddress(kernel32, "WaitCommEvent")`. Once that was fixed, three more boundaries followed in turn:*
1. *`WS_BORDER` in `CreateWindowExA`;*
2. *an unhandled guest exception (`UnhandledExceptionFilter`);*
3. *an IO board input instruction (`in ax, dx`).*

## Windows 측정과 원본 확인 / Windows measurements and the original

- **원본 import**: Windows `--image-dump`의 복호화 이미지에서 이름 표를 모았다. facade에 없는 것은 kernel32 시리얼 함수 9개뿐이다: `SetCommState`, `GetCommState`, `SetCommTimeouts`, `PurgeComm`, `SetupComm`, `SetCommMask`, `ClearCommError`, `GetOverlappedResult`, `WaitCommEvent`.
- **`WS_BORDER` 창**(Windows 11, `scratchpad/border427`): `WS_POPUP | WS_VISIBLE | WS_BORDER` 창의 메시지 순서는 4th의 테두리 없는 창과 같다. 차이는 `DefWindowProc`의 `WM_NCCALCSIZE`가 사방을 1픽셀씩 줄인다는 것뿐이다(0,0,640,480 → 1,1,639,479). 그래서 `WM_SIZE`는 638×478(`0x01de027e`), `WM_MOVE`는 (1,1)이다. 스타일은 `WS_CLIPSIBLINGS`가 더해진 `0x94800000`이다.
- **입력 helper**: 예외 `C0000096`이 `0x0040B169`의 `in ax, dx`에서 났다. 원본에는 `0x44D410`의 포트 표(0x300~0x306)를 읽는 `in ax, dx` 루프가 두 곳 있다. RVA `0x0000b169`(보드 시작)와 `0x0000b4cb`(폴링)다. 출력은 기존에 확인된 `0x0000b565` 한 곳이다.

*Windows measurements and the original:*
- ***Original imports**: the name table was collected from the decrypted image of a Windows `--image-dump`. The only ones missing from the facades are nine kernel32 serial functions: `SetCommState`, `GetCommState`, `SetCommTimeouts`, `PurgeComm`, `SetupComm`, `SetCommMask`, `ClearCommError`, `GetOverlappedResult`, and `WaitCommEvent`.*
- ***A `WS_BORDER` window** (Windows 11, `scratchpad/border427`): a `WS_POPUP | WS_VISIBLE | WS_BORDER` window gets the same message sequence as 4th's borderless one. The only difference is that `DefWindowProc`'s `WM_NCCALCSIZE` insets each side by one pixel (0,0,640,480 → 1,1,639,479), so `WM_SIZE` is 638×478 (`0x01de027e`) and `WM_MOVE` is (1,1). The style reads `0x94800000`, with `WS_CLIPSIBLINGS` added.*
- ***The input helpers**: exception `C0000096` came from `in ax, dx` at `0x0040B169`. The original has two `in ax, dx` loops over the port table at `0x44D410` (0x300–0x306): RVA `0x0000b169` (board start) and `0x0000b4cb` (polling). Output stays the one confirmed helper at `0x0000b565`.*

## 결정 / Decisions

1. **시리얼 함수**: 9개를 kernel32 resolve-only로 둔다. 불리면 멈춘다. 이번 실행에서는 불리지 않았다.
   *Serial functions: the nine are kernel32 resolve-only exports, which stop if called; this run never calls them.*
2. **`WS_BORDER`**: `CreateWindowExA`가 `WS_BORDER`를 받는다. HLE `DefWindowProcA`의 `WM_NCCALCSIZE`는 측정대로 `WS_BORDER` 창이면 사각형을 1픽셀 줄인다. `WS_DLGFRAME`(그래서 `WS_CAPTION`)은 여전히 모델하지 않는다.
   *`WS_BORDER`: `CreateWindowExA` takes `WS_BORDER`, and the HLE `DefWindowProcA` insets the `WM_NCCALCSIZE` rectangle by one pixel for such a window, as measured. `WS_DLGFRAME` (and so `WS_CAPTION`) stays unmodelled.*
3. **`UnhandledExceptionFilter`**: CRT가 처리되지 않은 예외로 이것을 부르면 `EXCEPTION_POINTERS`에서 예외 코드·주소·인자를 읽는다. 그 내용으로 멈춰, 실행 결과에 무엇이 잘못됐는지 남긴다. Windows라면 이때 프로세스가 WER과 함께 끝난다. 게스트가 등록한 필터를 부르는 일은 모델하지 않는다.
   *`UnhandledExceptionFilter`: when the CRT calls it for an unhandled exception, it reads the exception's code, address, and parameters from the `EXCEPTION_POINTERS` and stops with them, so the run records what went wrong. On Windows the process would end with WER there; calling a filter the guest registered is not modelled.*
4. **Linux EZ2Dancer 보드**
   - Linux IO trap은 지금까지 word 폭 보드가 설정되면 꺼졌다. 이제 공용 `Ez2DancerIoPortBus`에 답한다.
   - 키 배치 표를 Windows 전용 `ez2dancer_keyboard_input.cpp`에서 공용 core `re2dj/input/ez2dancer_keyboard_map.h`로 옮겼다. Windows 입력 코드도 이 표를 쓴다. 단위 테스트가 `config/ez2dancer-io.example.ini`와 일치하는지 검사한다.
   - 입력 helper가 두 곳이라 프로필의 `legacy_io_in_rva`는 0으로 둔다. 읽기는 opcode로 잡고, 두 RVA는 주석과 프로필 설명에 적는다.

   *The Linux EZ2Dancer board:*
   - *The Linux IO trap used to turn itself off for a word-wide board; it now answers through the shared `Ez2DancerIoPortBus`.*
   - *The key bindings moved from the Windows-only `ez2dancer_keyboard_input.cpp` into the shared core `re2dj/input/ez2dancer_keyboard_map.h`, which the Windows input code uses as well; a unit test checks them against `config/ez2dancer-io.example.ini`.*
   - *With two input helpers, the profile's `legacy_io_in_rva` stays 0, so reads are matched by opcode; both RVAs are recorded in comments and in the profile's note.*

## 범위 밖 / Out of scope

- **코인 입력**: 공용 보드의 코인 입력(`0x304` bit 0)은 추정이다. 이번에 두 host 모두 크레딧이 오르지 않는다고 적었으나, 키 전달이 실패한 탓의 오판이었다. [작업 428](20260929-428-ez2d2m-serial.md)에서 두 host 모두 크레딧이 오르는 것을 확인했다.
  *The coin input: the shared board's coin input (`0x304` bit 0) is inferred. This task recorded that the credit count rose on neither host, but that was a misreading caused by the key not reaching the game; [task 428](20260929-428-ez2d2m-serial.md) confirmed that it rises on both hosts.*
