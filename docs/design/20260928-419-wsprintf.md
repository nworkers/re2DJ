# 작업 419 설계 — wsprintfA / Task 419 design — wsprintfA

선행: [작업 418 설계](20260928-418-heap-validate.md)

## 배경 / Background

작업 418 뒤 Linux의 EZ2DJ 1st는 `user32!wsprintfA`에서 멈췄다. 복호화 이미지에서 `wsprintfA` 호출 지점과 그 앞에 push되는 서식 문자열을 모두 찾았다. 1st가 쓰는 서식은 `%d`, `%02d`, `%6d`, `%s`뿐이다(예: `Songs\%s\ez`, `A_bomb%02d`, `%s.bmp`, `FPS: %02d`).

`wsprintfA`는 가변 인자 cdecl 함수다. 그런데 Linux dispatch는 선언된 개수만큼만 인자를 handler에 넘겼다.

*After Task 418, EZ2DJ 1st on Linux stopped at `user32!wsprintfA`. Every `wsprintfA` call site in the decrypted image was found together with the format string pushed before it. 1st uses only `%d`, `%02d`, `%6d`, and `%s` (e.g. `Songs\%s\ez`, `A_bomb%02d`, `%s.bmp`, `FPS: %02d`).*

*`wsprintfA` is a variadic cdecl function, while the Linux dispatch handed handlers only the declared number of arguments.*

## Windows 측정 / Windows measurements

Windows 11에서 32비트 probe로 약 60개 서식을 측정했다(`scratchpad/wsp419`). 결과는 단위 테스트 `CheckWsprintfFormat`에 그대로 옮겼다. 요점은 다음과 같다.

- 형식 문법: `%[-#]...[0][width][.precision][h|l|w|I64]type`.
  - `-`와 `#`는 순서 없이 몇 번이든 올 수 있다. 그다음에 `0`이 온다.
  - `0` 뒤의 `#`나 `-`, 그리고 `+`, 공백, `*`는 형식 문자로 읽힌다.
- 모르는 형식 문자(`q`, `+`, `*`, `o`, `%` 포함)는 그 문자만 쓴다. 폭은 적용되지 않고 인자도 쓰지 않는다. 예: `%q%d`(1, 2) → `q1`.
- 서식이 형식 지정 도중에 끝나면(`abc%`, `%5`) 출력도 거기서 끝난다.
- 숫자 형식:
  - `h`는 `d`와 `i`만 16비트 부호 있는 값으로 자른다. `%hu`, `%hx`는 32비트를 그대로 쓴다.
  - 정밀도는 최소 자릿수다. 숫자는 언제나 한 자리 이상이다: `%.0d`(0) → `0`.
  - `0` 채움은 정밀도가 없고 `-`도 없을 때만 부호 뒤에 채운다: `%06d`(-42) → `-00042`, `%06.3d`(7) → `   007`.
  - `#`의 `0x`/`0X`는 폭에 들어가지 않고 채움 공백 뒤에 붙는다: `%#6x`(255) → `    0xff`, `%#05x` → `0x000ff`, `%#x`(0) → `0x0`.
  - `%p`는 정밀도 8의 대문자 16진수다: `%p`(0x1234) → `00001234`, `%.2p` → `AB`, `%#p` → `0X000000AB`.
  - `%I64d/u/x/X`는 두 워드를 쓴다.
  - `%lld`는 `l` 뒤의 `l`을 모르는 형식 문자로 읽는다: `ld`.
- 문자열·문자 형식:
  - NULL `%s`는 빈 문자열이다. 정밀도는 최대 길이다: `%.s` → 빈 문자열.
  - `0` 채움은 문자열과 문자에도 적용된다: `%05s` → `000ab`, `%03c` → `00q`.
  - `%hs`, `%hc`는 ANSI다.
- 출력은 1024자까지 쓰고 그 뒤에 NUL을 쓴다. 반환값은 쓴 글자 수(최대 1024)다.
- last error는 바뀌지 않는다.

*About 60 formats were measured with a 32-bit probe on Windows 11 (`scratchpad/wsp419`), and the results are carried as-is into the unit test `CheckWsprintfFormat`. The main points:*
- *Syntax: `%[-#]...[0][width][.precision][h|l|w|I64]type`. `-` and `#` may come in any order, any number of times, and `0` comes after them. A `#` or `-` after `0`, and `+`, space, and `*`, are read as the type.*
- *An unknown type (including `q`, `+`, `*`, `o`, and `%`) writes only itself: no width is applied and no argument is taken. For example, `%q%d` with (1, 2) gives `q1`.*
- *A format that ends inside a specification (`abc%`, `%5`) ends the output there.*
- *Numbers:*
  - *`h` truncates only `d` and `i` to a signed 16-bit value; `%hu` and `%hx` keep all 32 bits.*
  - *Precision is the minimum digit count, and a number always has at least one digit: `%.0d` with 0 gives `0`.*
  - *Zero fill applies only without a precision and without `-`, and goes after the sign: `%06d` with -42 gives `-00042`, `%06.3d` with 7 gives `   007`.*
  - *`#`'s `0x`/`0X` is not counted in the width and goes after the fill spaces: `%#6x` with 255 gives `    0xff`, `%#05x` gives `0x000ff`, `%#x` with 0 gives `0x0`.*
  - *`%p` is uppercase hex with precision 8: `%p` with 0x1234 gives `00001234`, `%.2p` gives `AB`, `%#p` gives `0X000000AB`.*
  - *`%I64d/u/x/X` take two words.*
  - *`%lld` reads the `l` after `l` as an unknown type: `ld`.*
- *Text:*
  - *A NULL `%s` is empty, and precision is the maximum length: `%.s` gives an empty string.*
  - *Zero fill applies to text too: `%05s` gives `000ab`, `%03c` gives `00q`.*
  - *`%hs` and `%hc` are ANSI.*
- *The output is written up to 1024 characters, followed by a NUL; the return value is the count written (at most 1024).*
- *The last error does not change.*

## 결정 / Decisions

1. 서식 처리는 공용 core `re2dj::hle::FormatWsprintf`(`include/re2dj/hle/wsprintf.h`)에 둔다. 측정 결과로만 새로 작성했다. 인자는 호출자가 주는 워드 판독기와 문자열 판독기로 읽는다. 그래서 core는 guest 메모리를 모른다.
   *Formatting lives in the shared core `re2dj::hle::FormatWsprintf` (`include/re2dj/hle/wsprintf.h`), written fresh from the measurements alone. It reads arguments through a word reader and a string reader the caller provides, so the core knows nothing of guest memory.*
2. wide 텍스트(`l`이나 `w`와 함께 쓴 `s`·`c`, `S`, `C`)와 `%I64s/c/p`는 측정하지 않았다. 추측하지 않고 멈춘다.
   *Wide text (`s` or `c` with `l` or `w`, `S`, `C`) and `%I64s/c/p` were not measured; they stop rather than guess.*
3. `ImportCall`에 `arguments_address`(guest 스택에서 첫 인자의 주소)를 더한다. Linux dispatch가 이를 채운다. `wsprintfA`는 선언 인자 두 개(`lpOut`, `lpFmt`)를 받는 cdecl export다. 나머지 인자는 `arguments_address + 8`부터 읽는다. 주소가 없는 host(현재 Windows의 `ImportDispatcher`)에서는 멈춘다. NULL `lpOut`이나 `lpFmt`는 Windows에서 fault가 나는 경우라 멈춘다.
   *`ImportCall` gains `arguments_address`, the guest-stack address of the first argument, which the Linux dispatch fills. `wsprintfA` is a cdecl export with two declared arguments (`lpOut`, `lpFmt`) and reads the rest from `arguments_address + 8`. A host that gives no address (today's Windows `ImportDispatcher`) stops. A NULL `lpOut` or `lpFmt` faults on Windows and stops.*
4. API 로그는 서식 문자열을 인자 텍스트로 보인다.
   *The API log shows the format string as the argument text.*
