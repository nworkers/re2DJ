# 작업 399 설계 — FindFirstFileA와 곡·스타일 목록 / Task 399 design — FindFirstFileA and style listings

선행: [작업 393 설계](20260927-393-current-directory.md), [작업 397 설계](20260927-397-linux-host-input.md)

## 배경 / Background

작업 397에서 사용자가 코인을 넣고 시작하자, Linux의 4th는 스타일 선택 화면의 자원을 읽은 뒤 `kernel32!FindFirstFileA`에서 멈췄다. 게임은 `system\StreetMix\panel\STYLE_StreetMix*_0.pvi` 같은 패턴으로 이미지 디렉터리를 훑는다.

Windows 제품은 injected runtime의 VFS가 이 함수를 처리한다(`Re2djVfsFindFirstFileA`).
- CHD의 FAT32 디렉터리를 읽는다.
- 자체 와일드카드 판정으로 항목을 고른다.
- `WIN32_FIND_DATAA`를 채운다: 디렉터리 또는 `FILE_ATTRIBUTE_NORMAL`, 크기, `DosDateTimeToFileTime`으로 바꾼 시각, 긴 이름.
- 일치 항목이 없으면 진짜 Windows 함수로 넘긴다.

이 규칙은 `src/platform/windows` 안에만 있었다.

*In Task 397, once a user had inserted coins and started, the 4th on Linux read the style select screen's resources and then stopped at `kernel32!FindFirstFileA`. The game sweeps image directories with patterns such as `system\StreetMix\panel\STYLE_StreetMix*_0.pvi`.*

*On the Windows product the injected runtime's VFS handles it (`Re2djVfsFindFirstFileA`):*
- *It reads the CHD's FAT32 directory.*
- *It picks entries with its own wildcard rule.*
- *It fills `WIN32_FIND_DATAA`: directory or `FILE_ATTRIBUTE_NORMAL`, size, times through `DosDateTimeToFileTime`, and the long name.*
- *With no match it falls through to the real Windows function.*

*These rules lived only under `src/platform/windows`.*

### 측정 / Measurements

32비트 PowerShell(P/Invoke)에서 NTFS 임시 디렉터리로 측정했다(Windows 11).

| 경우 / Case | 결과 / Result |
| --- | --- |
| 성공 / success | handle, last error 그대로 / *unchanged* |
| 목록 끝 / end (`FindNextFileA`) | FALSE, 18 (`ERROR_NO_MORE_FILES`) |
| 일치 없음(디렉터리 있음) / no match, directory exists | 2 |
| 디렉터리 없음 / missing directory | 3 |
| `Songs\`(빈 패턴 / empty pattern) | 87 |
| 빈 이름, NULL / empty name, NULL | 3 |
| 와일드카드 없는 이름 / a name without wildcards | 그 항목 / *that entry* |
| `FindClose` 성공 / success | TRUE, last error 그대로 / *unchanged* |
| NTFS 목록 / NTFS listing | `.`, `..` 포함, 파일 속성 0x20 / *with `.` and `..`; files 0x20* |

## 결정 / Decisions

1. **목록 규칙은 core로.** `re2dj/storage/guest_find.h`에 다음을 둔다. Windows VFS는 `WildcardMatch`와 `PopulateFindData`에서 core를 부른다(구조체 배치는 static_assert로 맞춤).
   - `MatchesFindPattern`: 제품의 와일드카드 판정.
   - `DosDateTimeToFileTime`: 시간대를 적용하지 않는 변환. Windows 단위 테스트가 모든 날짜와 여러 시각에서 Win32 함수와 일치하는지 확인한다.
   - `DescribeFindEntry`: `WIN32_FIND_DATAA` 구성.

   목록 내용은 제품 규칙 그대로다. FAT32 목록에 없는 `.`, `..`을 넣지 않고, 파일은 `FILE_ATTRIBUTE_NORMAL`이다. NTFS의 Windows 11과 다른 이 두 점은 두 host에서 같게 유지한다.

   ***The listing rules move to the core.** `re2dj/storage/guest_find.h` holds the following; the Windows VFS calls it from `WildcardMatch` and `PopulateFindData`, with the struct layout pinned by static_assert:*
   - *`MatchesFindPattern`: the product's wildcard rule.*
   - *`DosDateTimeToFileTime`: conversion with no time zone applied. A Windows unit test checks it against the Win32 function for every date at several times.*
   - *`DescribeFindEntry`: how `WIN32_FIND_DATAA` is filled.*

   *The listing stays the product's: no `.` or `..` (the FAT32 listing has none), and files are `FILE_ATTRIBUTE_NORMAL`. These two departures from Windows 11 on NTFS are kept alike on both hosts.*
2. **Linux 검색.** `GuestFiles::FindFirst/FindNext/FindClose`를 둔다. `GuestFileSource::ListDirectory`로 이미지 디렉터리를 이미지의 순서대로 읽는다.
   - 디렉터리 부분은 다른 경로처럼 현재 디렉터리를 기준으로 푼다. 마지막 요소가 패턴이다.
   - 오류는 측정값이다. 제품은 이 경우를 host 함수에 넘기므로, 그 결과는 host 경로에 따라 달라진다.
   - 루트 밖 검색은 모델 밖으로 멈춘다.
   - 검색 handle은 guest의 공용 handle 공간에서 나온다.

   ***The Linux search.** `GuestFiles::FindFirst/FindNext/FindClose`, reading image directories in the image's order through `GuestFileSource::ListDirectory`:*
   - *The directory part resolves against the current directory like any path, and the last part is the pattern.*
   - *The errors are the measured ones; the product hands these cases to the host function, whose answer depends on host paths.*
   - *A search outside the root stops as unmodelled.*
   - *Search handles come from the guest's shared handle space.*
3. **kernel32.**
   - `FindFirstFileA`: 성공하면 last error를 그대로 둔다. 실패하면 `INVALID_HANDLE_VALUE`와 오류, NULL 이름이면 3이다. 데이터 포인터가 NULL이면 제품처럼 87이다.
   - `FindNextFileA`: 끝이면 18, 모르는 handle이면 6이다.
   - `FindClose`: 모르는 handle이면 6이다.

   ***kernel32:***
   - *`FindFirstFileA`: success leaves the last error alone; failure is `INVALID_HANDLE_VALUE` with the error, 3 for a null name, and 87 for a null data pointer as in the product.*
   - *`FindNextFileA`: 18 at the end, 6 for an unknown handle.*
   - *`FindClose`: 6 for an unknown handle.*
4. **진단.** Linux CLI에 `--api-log-calls <n>`을 둔다. API 기록을 처음 n번까지 남기며, 0은 전부다. 기본값 32,768 뒤에서 일어나는 경계를 볼 때 쓴다.
   ***Diagnostics.** The Linux CLI gains `--api-log-calls <n>`, recording the first n calls in the API log (0 for all), for boundaries past the default 32,768.*
