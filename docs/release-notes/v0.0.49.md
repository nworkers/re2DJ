# re2DJ v0.0.49

## 변경 사항

- Autoplay 토글을 EZ2DJ 4th·5th·1st SE와 EZ2Dancer 2nd MOVE로 넓혔습니다.
  - 각 빌드의 복호화 덤프를 분석해 autoplay 플래그를 따로 찾았습니다. `ez2dj4th`(`0x3d369bfd`), `ez2dj5th`(`0x3f53377b`), `ez2dj1stse`(`0x3862df27`), `ez2d2m`(`0x3a5f074c`)입니다.
  - 주소는 빌드마다 다르므로, 런처는 실행 파일의 빌드 timestamp가 프로파일 선언과 일치할 때만 무장합니다.
  - 곡을 시작하기 전에 OSD에서 Autoplay를 체크하면 그 곡이 자동으로 연주됩니다.
  - 빌드마다 구조가 달랐습니다. 4th·5th는 3rd와 같은 데모 플래그 방식, 1st SE는 장면 엔진, EZ2Dancer 2nd MOVE는 클래스 쌍 구조였습니다.
  - EZ2DJ 1st Tracks는 데모 전용 플레이어 장면이 자동 연주를 직접 수행해 전환할 변수가 없습니다. 이 빌드에는 토글이 나타나지 않습니다.
- EZ2DJ 1st Tracks와 1st SE에서 효과음이 끝없이 반복되던 문제를 고쳤습니다.
  - 두 빌드는 효과음 버퍼를 만들 때 `DSBCAPS_STATIC`과 `DSBCAPS_GETCURRENTPOSITION2`를 함께 지정합니다. DirectSound HLE가 이를 배경음 링 버퍼로 분류해, 효과음이 끝에 도달해도 멈추지 않고 반복됐습니다.
  - 분류 규칙을 플랫폼 공용 함수로 옮기고 `DSBCAPS_STATIC` 버퍼를 제외했습니다. 360,448바이트 링 버퍼 규칙은 그대로 유지합니다.
  - 스트리밍 경로가 `DSBPLAY_LOOPING`을 따르도록 해, 반복 없이 재생한 버퍼는 한 바퀴 뒤 멈춥니다.
  - 일곱 타깃의 변경 전후 오디오 트레이스를 비교해 효과음 분류만 바뀌었음을 확인했습니다. 다른 빌드의 배경음은 영향이 없습니다.
- autoplay 탐색 절차를 `game-state-hunt` 스킬로 정리했습니다(`.agents/skills`).
  - Capstone 기반 분석 스크립트와 단계별 절차, 빌드 형태별 경로(장면 엔진, 클래스 쌍), 확인된 결과 표를 포함합니다.

- 단위 테스트 1,821건 전체 통과 (`checks: 1821, failures: 0`, Debug·Release 동일)

## English

# re2DJ v0.0.49

## Changes

- Extended the Autoplay toggle to EZ2DJ 4th, 5th and 1st SE, and to EZ2Dancer 2nd MOVE.
  - Each build's autoplay flag was located separately from its decrypted image: `ez2dj4th` (`0x3d369bfd`), `ez2dj5th` (`0x3f53377b`), `ez2dj1stse` (`0x3862df27`) and `ez2d2m` (`0x3a5f074c`).
  - Addresses differ per build, so the launcher arms the control only when the executable's build timestamp matches the profile's declaration.
  - Checking Autoplay in the OSD before starting a song plays that song automatically.
  - The builds differ in structure: 4th and 5th share 3rd's demo-flag arrangement, 1st SE is a scene engine, and EZ2Dancer 2nd MOVE pairs a normal and a demo class.
  - EZ2DJ 1st Tracks has no switchable variable, since its dedicated demo player scenes perform automatic play themselves, so no toggle appears for that build.
- Fixed endlessly repeating sound effects in EZ2DJ 1st Tracks and 1st SE.
  - Both builds create effect buffers with `DSBCAPS_STATIC` together with `DSBCAPS_GETCURRENTPOSITION2`. The DirectSound HLE classified those as background ring buffers, so an effect never stopped at its end.
  - The classification moved into a platform-neutral function that excludes `DSBCAPS_STATIC` buffers while keeping the 360,448-byte ring rule.
  - The streaming path now honors `DSBPLAY_LOOPING`: a buffer played without it stops after one pass.
  - Before-and-after audio traces of seven targets confirm that only effect classification changed; background audio in other builds is unaffected.
- Captured the autoplay hunt as the `game-state-hunt` skill (`.agents/skills`).
  - It carries the Capstone-based analysis scripts, the step-by-step procedure, paths for each build shape (scene engine, paired classes) and a table of confirmed results.

## Verification

- Full Windows x86 Debug and Release builds succeeded.
- All 1,821 unit test checks passed (`checks: 1821, failures: 0`, identical in Debug and Release).
- The CTest suite passed, excluding the already-hanging `re2dj_windows_vfs_runtime_probe`.
- Automatic play through the OSD Autoplay toggle was verified in 4th, 5th, 1st SE and EZ2Dancer 2nd MOVE.
- Listening confirmed that the 1st SE effect repeat is gone and that other builds' background audio is unaffected.

The original game executable, HDD data, and CHD images are not included in the distribution package.
