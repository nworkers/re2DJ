## 진행 / Progress

첫 측정 스크립트는 `0x80000000`을 `uint` 인자로 넘기다 실패했다. PowerShell에서 이 값은 음수이기 때문이다. 알려진 대로 인자를 int로 바꿔 다시 측정했다.

*The first measuring script failed passing `0x80000000` to a `uint` parameter, since PowerShell reads that literal as negative; as known, the parameters were switched to int and it was measured again.*

파일 handle에 `FILE_TYPE_DISK`로 답하자 CRT가 `aw-logo.ezw`를 열었다. 게임은 Amuse World 로고 장면으로 넘어갔다. 실행 중 캡처(원본 화면, 저장소 밖 scratchpad에만 보관)에 로고와 크레딧 표시가 보였다. 전체 기록의 프레임 구성은 다음과 같다.

| 프레임 수 / Frames | 내용 / Contents |
| --- | --- |
| 300 | WARNING |
| 129 + 61 | 전환 / *transition* |
| 20 | clear 1, draw 5 / *1 clear, 5 draws* |
| 50 | clear 2, draw 6 / *2 clears, 6 draws* |
| 30 | clear 2, draw 8 / *2 clears, 8 draws* |
| 37 | clear 2, draw 9 / *2 clears, 9 draws* |

그 뒤 진단용 호출 한도 32,768번에 닿아 멈췄다. 모델 밖 API에서 멈춘 것은 아니다.

*With `FILE_TYPE_DISK` for file handles the CRT opened `aw-logo.ezw` and the game moved on to the Amuse World logo scene; a mid-run capture (of the original screen, kept only outside the repository in the scratchpad) showed the logo and the credit display. The whole log's frames are above. The run then stopped at the diagnostic limit of 32,768 calls, not at an unmodelled API.*

이제 두 폭 모두 고정된 호출 수에서 멈추므로, 멈추는 지점은 실제 시계에 따른 프레임 속도와 IO 폴링 횟수에 좌우된다. 그래서 끝 256줄과 IO 읽기 수(3,783 대 3,777)는 두 폭이 다르다. 시계와 무관한 부분은 같다.

- 앞 256줄
- hardlock 83번
- IO 쓰기 2,516번
- 연 파일 45개의 이름과 순서

*Both widths now stop at a fixed call count, so where they stop depends on frame pacing by the real clock and on how often the IO board is polled. The last 256 lines and the IO read counts (3,783 against 3,777) therefore differ between widths, while everything independent of the clock matches: the first 256 lines, 83 hardlock requests, 2,516 IO writes, and the names and order of the 45 files opened.*

## 변경 / Changes

- **kernel32**: `GetFileType`이 열린 guest 파일에 `FILE_TYPE_DISK`로 답하고, last error는 그대로 둔다. / ***kernel32:** `GetFileType` answers `FILE_TYPE_DISK` for open guest files, leaving the last error alone.*
- **단위 테스트**: 열린 파일의 종류와 last error 유지, 닫은 handle의 0과 `ERROR_INVALID_HANDLE`. / ***Unit tests:** an open file's type with the last error kept, and a closed handle's 0 with `ERROR_INVALID_HANDLE`.*
