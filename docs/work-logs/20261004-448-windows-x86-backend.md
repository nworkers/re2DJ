# 작업 448 작업 로그 — Windows x86 in-process backend / Task 448 work log — the Windows x86 in-process backend

설계: [20261004-448-windows-x86-backend.md](../design/20261004-448-windows-x86-backend.md) · 지시서: [20261004-448-windows-x86-backend.md](../work-orders/20261004-448-windows-x86-backend.md)

## 2026-10-04

- **설계 변경**: 작업 446 설계는 "실제 TEB를 그대로 게스트 TEB로"였다. 구현 전에 공용 HLE를 보니 TLS 슬롯(TEB+0xE10), ClientId(+0x20), LastError(+0x34), `RtlUnwind`의 SEH 체인(+0)을 TEB에 직접 쓴다. 실제 TEB를 공유하면 SDL의 TLS 슬롯과 host의 `GetCurrentThreadId`가 깨진다. 그래서 448 설계에서 **그림자 TEB + fs:0 동기화**로 바꿨다. MASM 대신 MSVC naked 인라인 asm을 쓰는 것도 448 설계에서 정했다.
- **VEH와 스택**: VEH는 fault 스레드의 스택, 게스트 ESP 바로 아래에서 돈다. 공용 SEH 배달은 그 자리에 예외 레코드를 쓰므로 VEH가 직접 배달하지 않는다. VEH는 게스트 레지스터를 `g_pending`에 담고 `GuestFaultTrampoline`으로 돌려보내며, trampoline이 스레드별 배달 스택(32 KiB, thread_local)에서 배달하고 정한 레지스터로 게스트에 들어간다. instruction trace와 legacy I/O는 스택에 쓰지 않으므로 VEH에서 바로 처리한다.
- **구현 파일**
  - `src/platform/windows/native_host_services.cpp`, `native_host_protection.h`
  - `src/platform/windows/x86/native_guest_transition.{h,cpp}`: `EnterGuestRun`·`EscapeGuestRun`, `CallGuestEntry`·`CallGuestThread`·`CallGuestTls`(fs:0 = -1로 게스트 체인 시작), `CallGuestStdcallWords`(그림자 TEB의 게스트 체인을 fs:0에 올리고 돌아오면 되돌림)
  - `native_import_bridge.cpp`: bridge가 fs:0을 스택 슬롯으로 빼고 -1로 둔 채 handler를 부르며, handler 앞뒤로 슬롯 ↔ 그림자 TEB+0을 복사한다.
  - `native_process_bootstrap.cpp`: 그림자 TEB·PEB, VEH(`STATUS_*` → x86 trap, INT3는 Eip+1로 Linux 의미에 맞춤), 배달 trampoline, `CreateThread` 게스트 스레드(준비 이벤트로 스택 범위를 받은 뒤 반환), `ExitNativeGuestProcess`·`AbandonNativeGuestRun`.
  - `native_low_memory.cpp`, `native_in_process_probe.cpp`, `x86/README.md`
  - 공용: `NativeGuestThread::fs_teb`(게스트가 FS로 보는 TEB, 0이면 `teb`와 같음). thread probe는 게스트가 FS로 읽어 저장한 TEB를 이것과 비교한다. thread probe의 출력 접두어를 인자로 받게 해(`linux-x86`, `windows-x86` 등) OS 이름이 들어간다.
  - MSVC 경고 C4733(fs:0에 안전하지 않은 처리기 등록)은 세 파일에서 이유를 적고 껐다. 처리기를 등록하는 것이 아니라 체인을 옮기기 때문이다.
  - CMake: `RE2DJ_NATIVE_RUNNER_SOURCES`로 공용 러너 목록을 묶고 Linux backend와 새 `re2dj_windows_native_backend`가 함께 쓴다. probe는 `/BASE:0x60000000 /DYNAMICBASE:NO /LARGEADDRESSAWARE /STACK:0x1000000`로 링크하고 CTest에 등록했다.

  *Design change: task 446's design shared the real TEB with the guest, but the shared HLE writes TLS slots (TEB+0xE10), ClientId (+0x20), LastError (+0x34) and `RtlUnwind`'s SEH chain (+0) into the TEB itself, which would break SDL's TLS slots and the host's `GetCurrentThreadId`; design 448 switches to a **shadow TEB with fs:0 kept in step**, and to MSVC naked inline asm instead of MASM. The VEH runs on the faulting thread's stack right below the guest's ESP, where shared SEH delivery writes the exception record, so it does not deliver itself: it stores the guest registers in `g_pending` and sends the guest to `GuestFaultTrampoline`, which delivers on a per-thread 32 KiB delivery stack and enters the guest with the registers delivery chose; the instruction trace and legacy I/O write no stack and are handled in the VEH directly. Files: the Windows host services and PAGE_* converter; `x86/native_guest_transition.{h,cpp}` (`EnterGuestRun`/`EscapeGuestRun`, `CallGuestEntry`/`CallGuestThread`/`CallGuestTls` starting the guest chain at fs:0 = -1, `CallGuestStdcallWords` putting the shadow TEB's guest chain on fs:0 and taking it back); `native_import_bridge.cpp`, whose bridge moves fs:0 to a stack slot, leaves -1 while the handler runs and copies slot ↔ shadow TEB+0 around it; `native_process_bootstrap.cpp` (shadow TEB and PEB, the VEH mapping `STATUS_*` to x86 traps with INT3 at Eip+1 to match Linux, the delivery trampoline, `CreateThread` guest threads returning once a ready event brings their stack bounds, `ExitNativeGuestProcess`, `AbandonNativeGuestRun`); `native_low_memory.cpp`, `native_in_process_probe.cpp`, `x86/README.md`. Shared: `NativeGuestThread::fs_teb`, the TEB guest code sees through FS (zero meaning `teb`), which the thread probe now compares the TEB the guest stored against; the thread probe's output names its host through its argument (`linux-x86`, `windows-x86`). MSVC warning C4733 is disabled with a reason in the three files, which move chains rather than register handlers. CMake groups the shared runner in `RE2DJ_NATIVE_RUNNER_SOURCES` for the Linux backend and the new `re2dj_windows_native_backend`; the probe links with `/BASE:0x60000000 /DYNAMICBASE:NO /LARGEADDRESSAWARE /STACK:0x1000000` and is registered with CTest.*

- **검증**
  - Windows x86 Debug(MSVC, 경고를 오류로): 전체 build 성공, CTest 8개 통과.
  - `re2dj_windows_native_in_process_probe`: 합성 PE32 import 2개와 TLS callback(FS self·스택 범위), 동적 thunk(cdecl, stdcall 7인자·ESP 보존), instruction trace와 `ud2` fault(`STATUS_ILLEGAL_INSTRUCTION`), import에서 ExitProcess(7), 게스트 스레드(그림자 TEB 0x04800000, 게스트가 FS로 본 TEB는 실제 TEB, 반환 0xb9)와 게스트 스레드 fault, **게스트 SEH**(핸들러가 `ud2`와 널 읽기를 넘겨 두 번 재개, 거절하면 run이 `ud2` 주소에서 끝남), 그림자 TEB 확인(run 뒤 host의 `GetCurrentThreadId()`와 `TlsGetValue` 그대로).
    - 첫 실행에서 thread probe만 실패했다. 게스트가 FS로 읽은 TEB(실제)와 HLE의 TEB(그림자)가 같다는 Linux 전제를 검사했기 때문이고, 설계대로의 차이다. `fs_teb`를 더해 고쳤다.
  - WSL Linux x64·x86 debug(경고를 오류로): build 성공, CTest 각 5개 통과. i386 probe 출력에 새 접두어(`linux-x86-thread-probe`)가 나온다.
  - **아직 하지 않은 것**: 실제 게임을 Windows in-process로 돌리는 것은 449(CLI 전환)에서 한다.

  *Verification: the Windows x86 Debug build (MSVC, warnings as errors) passes in full with 8 CTest tests. `re2dj_windows_native_in_process_probe` covers the synthetic PE32's two imports and TLS callback (FS self and stack bounds), dynamic thunks (cdecl, and stdcall with seven arguments and ESP preserved), the instruction trace and a `ud2` fault (`STATUS_ILLEGAL_INSTRUCTION`), ExitProcess(7) from an import, a guest thread (shadow TEB 0x04800000, the guest seeing the real TEB through FS, returning 0xb9) and a guest thread fault, **guest SEH** (a handler stepping over a `ud2` and a null read resumes twice; declining ends the run at the `ud2`), and the shadow TEB (the host's `GetCurrentThreadId()` and `TlsGetValue` intact after the run). Only the thread probe failed at first, checking Linux's assumption that the TEB the guest reads through FS (real) is the HLE's (shadow), a difference by design, fixed with `fs_teb`. The WSL Linux x64 and x86 debug builds (warnings as errors) pass with 5 CTest tests each, the i386 probe printing the new prefix (`linux-x86-thread-probe`). Running a real game in-process on Windows is 449's (the CLI switch).*
