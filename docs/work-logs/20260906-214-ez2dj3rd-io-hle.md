# 작업 로그: ez2dj3rd I/O HLE 연결

## 한국어

### 결과

`ez2dj3rd` 프로파일에서 `--io-config`가 더 이상 무시되지 않도록 공용 keyboard-to-I/O-board HLE를 연결했습니다. 3rd 실행 파일의 helper RVA는 확인되지 않았으므로 2nd·4th의 주소를 복사하지 않았습니다.

프로파일은 `legacy_io_ports`, `legacy_io_ports_default`, `legacy_io_port_range_fallback`을 사용합니다. fallback은 byte `IN AL,DX`(`0xec`)와 byte `OUT DX,AL`(`0xee`)만 후보로 삼고, 최종 처리는 `LegacyIoPortBus`가 지원하는 포트에서만 수행합니다. 지원되지 않는 포트나 opcode는 원래 예외 경로로 전달됩니다. injected runtime은 기존 export만 사용하며, helper RVA가 둘 다 0인 경우에만 이 제한 fallback을 활성화합니다.

### 변경 파일

- `include/re2dj/target/target_profile.h`: 미확인 helper RVA를 위한 3rd 전용 fallback 정책 필드 추가
- `src/target/target_profile.cpp`: `ez2dj3rd`의 legacy I/O 기본 정책 활성화
- `src/platform/windows/original_process_backend.cpp`: fallback launcher 인자 전달 및 zero-RVA 검증 완화
- `src/platform/windows/injected_runtime.cpp`: 지원 opcode·포트에 대한 범위 fallback 처리
- `src/tools/windows_x86_launcher_probe/main.cpp`: debugger trap과 runtime 준비 경로에 fallback 정책 연결
- `src/tools/windows_product_loader_probe/main.cpp`: 3rd 인자 계약 검증 추가
- `tests/unit/target_profile_test.cpp`: 3rd 프로파일 정책 검증 갱신
- `docs/design/20260906-214-ez2dj3rd-io-hle.md`: 설계
- `docs/work-orders/20260906-214-ez2dj3rd-io-hle.md`: 작업 지시서
- `docs/analysis/ez2dj3rd-hardlock-function-0e.md`: 확인됨·미확정 범위 갱신
- `ARCHITECTURE.md`: 3rd raw-I/O fallback 구조 갱신

## English

### Result

The shared keyboard-to-I/O-board HLE is now connected to the `ez2dj3rd` profile, so `--io-config` is no longer ignored. The 3rd executable's helper RVA is not confirmed, so no address from 2nd or 4th was copied.

The profile uses `legacy_io_ports`, `legacy_io_ports_default`, and `legacy_io_port_range_fallback`. The fallback considers only byte `IN AL,DX` (`0xec`) and byte `OUT DX,AL` (`0xee`), and `LegacyIoPortBus` still decides whether the port is supported. Unsupported ports and opcodes remain on the original exception path. The injected runtime uses only existing exports and enables this bounded fallback only when both helper RVAs are zero.

### Verification

- `git diff --check`: passed
- Windows x86 Debug build of the product, injected runtime, and launcher probe: passed
- Focused CTest: 2/2 passed
- Final product run reached runtime handoff and recorded `io_runtime_prepared=true`, `handoff_observed=true`, and `iat_verified=true`
- Final diagnostic: `logs/windows_x86_launcher_probe/ez2dj3rd/20260906-210707-367.jsonl`
- Final `io_port_runtime`: `in_rva=0x00000000`, `out_rva=0x00000000`, `port_range_fallback=true`, `status=prepared`
- The detached original process exited with `0xc0000005`. This task confirms I/O-HLE preparation and connection only; it does not confirm the actual 3rd raw-I/O helper address or successful post-Hardlock execution.

The existing user change in `config/ez2dj-io.example.ini` was preserved and is not part of the commit.
