- **공용 코어**
  - `include/re2dj/input/gamepad.h`, `src/input/gamepad.cpp`: `GamepadControl`(29개 컨트롤), `ParseGamepadControlName`(`ParseKeyName`과 같은 규약), `GamepadControlName`, `GamepadControls`(bitset 32), `GamepadControlHeld`.
  - 바인딩 표 세 개에 `default_gamepad` 이름을 더했다. 기본값은 설계의 표와 같다.
  - `include/re2dj/input/io_bindings.h`, `src/input/io_bindings.cpp`: 풀린 바인딩 `Ez2DjIoBindings`·`Ez2DancerIoBindings`·`IoBindings`, 기본값 함수, INI 본문 로더 `LoadEz2DjIoBindings`·`LoadEz2DancerIoBindings`. INI 판정은 `hle::FindPrivateProfileValue`·`PrivateProfileStringValue`·`ParsePrivateProfileInt`로 한다. 섹션은 `[buttons]`·`[turntables]`·`[gamepad]`.
  - `hle::HostInputState::gamepad`.
  - `config/ez2dj-io.example.ini`, `config/ez2dancer-io.example.ini`: `[gamepad]` 섹션을 기본값으로 더했다.
- **SDL3 reader**: `include/re2dj/input/sdl3_gamepad_reader.h`, `src/input/sdl3_gamepad_reader.cpp`(`re2dj_sdl3_gamepad` 라이브러리). `SDL_INIT_GAMEPAD`가 이미 켜져 있으면 빌리고 아니면 소유한다. 버튼 19개와 축 6개를 컨트롤로 바꾼다(축 문턱 16384). `CMakeLists.txt`: `SDL_JOYSTICK ON`, `SDL_HIDAPI ON`, `SDL_HIDAPI_LIBUSB OFF`.
- **Linux 연결**
  - `LinuxHostPresentation`: 창을 연 뒤 reader를 초기화하고(`input: gamepads ready, N connected`; 실패는 경고), `HandleEvent`가 장치 이벤트를 reader에 먼저 넘겨 `input: gamepad added/removed: <name>`을 남기며, `Present`가 펌프 뒤에 `input_.gamepad`를 채운다.
  - `native_legacy_io`: `SetNativeLegacyIo`가 `IoBindings`를 받고, 항목마다 키 또는 패드 컨트롤이 쥐어지면 눌림. `step`도 바인딩에서 온다.
  - `OriginalRunEnvironment::io_bindings`(기본값으로 초기화), `native_continuation_observation`이 넘긴다.
  - `main.cpp`: `--io-config`를 Linux에서도 받는다. 파일을 읽어 두 게임의 섹션을 모두 풀고(`LoadLinuxIoBindings`), 없거나 비면 기본값, legacy I/O가 없는 프로파일이면 무시하고 로그. 읽기 실패·모르는 이름·`step` 범위는 `EXECUTION_FAILED`로 끝난다. 런처의 자식은 부모 인자를 물려받으므로 `--io-config`도 따라간다.
- **빌드 패키지**: `ci.yml`(x64, i386), `release.yml`, Linux 빌드 가이드에 `libudev-dev`.
- **테스트**: `tests/unit/gamepad_bindings_test.cpp`(이름 파싱, 기본값과 예제 INI `[gamepad]` 대조, 로더의 기본값·부분 덮어쓰기·`NONE`·오류·`step`), `tests/unit/sdl3_gamepad_reader_test.cpp`(`re2dj_sdl3_gamepad_test`: SDL 가상 조이스틱으로 버튼·축·추가·제거).
- **문서**: README(옵션 설명, 게임패드 문단), ARCHITECTURE, `docs/kb/sdl3-gamepad-input.md`와 kb 색인.

  *Shared core: `input/gamepad.h`/`.cpp` (29 `GamepadControl`s, `ParseGamepadControlName` under `ParseKeyName`'s contract, `GamepadControlName`, the 32-bit `GamepadControls` and `GamepadControlHeld`); `default_gamepad` names in the three binding tables as the design's tables; `input/io_bindings.h`/`.cpp` with the resolved `Ez2DjIoBindings`, `Ez2DancerIoBindings` and `IoBindings`, their defaults and the INI-text loaders over `hle::FindPrivateProfileValue`, `PrivateProfileStringValue` and `ParsePrivateProfileInt` (sections `[buttons]`, `[turntables]`, `[gamepad]`); `hle::HostInputState::gamepad`; and a `[gamepad]` section at the defaults in both example INIs. The SDL3 reader `input/sdl3_gamepad_reader.h`/`.cpp` (library `re2dj_sdl3_gamepad`) borrows or owns `SDL_INIT_GAMEPAD` and turns 19 buttons and 6 axes (threshold 16384) into controls; CMake sets `SDL_JOYSTICK ON`, `SDL_HIDAPI ON`, `SDL_HIDAPI_LIBUSB OFF`. Linux: `LinuxHostPresentation` initialises the reader after the window opens (`input: gamepads ready, N connected`, a failure a warning), hands device events to it first and logs `input: gamepad added/removed: <name>`, and fills `input_.gamepad` after `Present`'s pump; `native_legacy_io` takes `IoBindings` through `SetNativeLegacyIo` and holds an entry when its key or pad control is, with `step` from the bindings; `OriginalRunEnvironment::io_bindings` (defaulted) is passed by `native_continuation_observation`; `main.cpp` accepts `--io-config` on Linux, resolving both games' sections through `LoadLinuxIoBindings`, defaults when absent, ignored with a log for a profile without legacy I/O, and `EXECUTION_FAILED` on an unreadable file, an unknown name or a `step` out of range, the launcher's child inheriting it with the other arguments. `libudev-dev` joins `ci.yml` (x64 and i386), `release.yml` and the Linux build guide. Tests: `gamepad_bindings_test.cpp` (name parsing, defaults against the example INIs' `[gamepad]`, the loader's defaults, partial overrides, `NONE`, errors and `step`) and `sdl3_gamepad_reader_test.cpp` (`re2dj_sdl3_gamepad_test`, a virtual joystick's buttons, axes, add and remove). Documents: README (option text and a gamepad paragraph), ARCHITECTURE, `docs/kb/sdl3-gamepad-input.md` and the kb index.*

- **검증**
  - WSL Ubuntu 24.04, `linux-x64-debug`(경고를 오류로): build 성공, CTest 5개 통과(`re2dj_sdl3_gamepad_test` 24개 검사).
  - CLI: `--io-config`에 `p1_1=Z`(모르는 컨트롤)와 없는 파일을 주면 `EXECUTION_FAILED`로 메시지와 함께 끝난다.
  - 6th 15초 실행(`timeout -s INT 15 re2dj ez2dj6th --io-config config/ez2dj-io.example.ini`, WSLg): 런처와 6th 자식 모두 `io config : .../ez2dj-io.example.ini`, `input: gamepads ready, 0 connected`, `Flip` 반복 후 창 닫힘으로 정상 종료.
  - `linux-x64-release` build와 `package_release.sh linux-x64`(`RE2DJ_MAX_GLIBC=2.99`, 이 host의 glibc 2.39): 패키지 생성. **NEEDED는 `libm.so.6 libc.so.6 ld-linux-x86-64.so.2`로 변함없다**(libudev는 `dlopen`). 패키지 3.35 MB(작업 442의 3.12 MB에서 SDL joystick·HIDAPI만큼 커짐).
    - 경고를 오류로 둔 release build는 `tests/unit/true_color_test.cpp`에서 GCC 13의 `-O3` `stringop-overflow` 오탐으로 멈췄다. 이 작업과 무관한 기존 파일이며, CMake의 GCC 12 전용 `-Wno-error=` 범위 밖이다. CI는 Debian 12의 GCC 12로 빌드하므로 영향이 없다. 여기서는 `RE2DJ_WARNINGS_AS_ERRORS=OFF`로 빌드해 NEEDED만 확인했다. GCC 13 이상에도 같은 완화를 적용할지는 별도 작업으로 둔다.
  - Windows x86 Debug(MSVC): build 성공, `re2dj_ez2dj_keyboard_input_test`·`re2dj_ez2dancer_keyboard_input_test`·`re2dj_unit_tests` 통과(바인딩 구조체 변경과 예제 INI의 `[gamepad]`가 Windows 키보드 입력에 영향 없음).
  - `re2dj_sdl3_gamepad_test`는 처음 Windows에서 3개 검사가 실패했다. 이 머신에 실제 Xbox Series X 컨트롤러가 꽂혀 있어 "패드 없음" 가정이 깨졌기 때문이다. 테스트가 이미 꽂힌 패드의 수와 유휴 상태를 기준값으로 빼도록 고쳤다. 고친 뒤 Windows(기준 패드 1개)와 Linux(0개) 모두 24개 검사 통과. 이 실패가 reader가 실제 장치를 열고(`added: Xbox Series X Controller`) 읽는 것을 보여 준 셈이다.
  - **하지 못한 것**: 실제 패드로 Linux에서 게임을 치는 확인. WSL에는 USB 패드가 없다. 사용자가 데스크톱 Linux 또는 스팀덱에서 6th를 실행해 `input: gamepad added: <이름>` 로그와 1P 키·턴테이블 입력을 확인한다. GitHub Actions의 i386 빌드(`libudev-dev:i386` 설치 포함)도 실행하지 못했다. Windows host의 게임패드 연결은 설계대로 범위 밖이다.
