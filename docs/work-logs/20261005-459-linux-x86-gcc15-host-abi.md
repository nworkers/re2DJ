## 2026-10-05

- **발견**: [작업 458](20261005-458-linux-desktop-validation.md)에서 사용자가 x86을 다시 확인하라고 했다. 처음에 multilib가 없다고 보고했으나, `dpkg` 출력을 잘못 걸러 생긴 오판이었다(`gcc-multilib`·`g++-multilib`·`libc6-dev-i386`, i386 아키텍처 모두 설치돼 있었다). 실제로 빌드하니 링크 오류(`undefined reference to g_native_host_gs_selector`, 3개 실행 파일)가 났다. `nm`으로 정의가 `_ZN…12_GLOBAL__N_1…E`로 맹글링된 것을 확인했다.
- 정의를 옮기자 빌드·CTest는 통과했지만, 4th·6th가 API 호출 1,820번째(`DirectDrawCreateEx`)에서 `guest fault signal 11`, `signal code=128`로 멈췄다. 실행 중 `/proc/<pid>/maps`를 10~20 ms마다 떠서 EIP를 `libLLVM.so.21.1`의 파일 오프셋 `0x4ace7aa`(가상 주소 `0x4acf7aa`)로 풀었다. `objdump` 결과 `movdqa %xmm0,0x20(%esp)`였다.
- **수정**: 설계 결정 1·2. 진단 중에 넣은 것은 없다.
- **NVIDIA Wayland**: 두 수정 뒤 x86은 X11에서 동작했지만, 네이티브 Wayland에서는 `SetCooperativeLevel`이 `eglCreateWindowSurface failed, reporting an error of EGL_SUCCESS`로 실패했다. 게스트 없는 x86 `re2dj_opengl_post_shader_probe`도 같았다. EGL 벤더를 고정하면 Mesa는 통과하고 NVIDIA는 실패했다. 외부 플랫폼을 하나씩 고정하면 `egl-wayland`(v1)는 12/12 통과, `egl-wayland2`는 실패했다. x64는 같은 NVIDIA 조합에서 통과한다. 32비트 NVIDIA 라이브러리(`libnvidia-gl-595:i386`, `libnvidia-egl-wayland1:i386`)는 설치돼 있었다. 가이드에 우회 방법을 적었다.
- **문서**: 설계·지시서, kb `i386-host-abi-at-guest-boundary.md`와 색인, 가이드 `linux-sdl3-build.md`의 NVIDIA 절(두 언어), ARCHITECTURE의 Linux x86 브리지 문단.

  *Discovery: during [task 458](20261005-458-linux-desktop-validation.md) the user asked for x86 to be checked again. The earlier report of missing multilib packages came from filtering `dpkg` output wrongly (`gcc-multilib`, `g++-multilib`, `libc6-dev-i386` and the i386 architecture were all present). The real build failed to link (`undefined reference to g_native_host_gs_selector` in three executables), and `nm` showed the definition mangled as `_ZN…12_GLOBAL__N_1…E`. With the definition moved, build and CTest passed, but 4th and 6th stopped at the 1,820th API call (`DirectDrawCreateEx`) with `guest fault signal 11`, `signal code=128`; snapshots of `/proc/<pid>/maps` every 10 to 20 ms resolved the EIP to file offset `0x4ace7aa` (virtual address `0x4acf7aa`) in `libLLVM.so.21.1`, which `objdump` shows as `movdqa %xmm0,0x20(%esp)`. Fix: design decisions 1 and 2, nothing left from the diagnosis. NVIDIA Wayland: after both fixes x86 ran under X11, but on native Wayland `SetCooperativeLevel` failed with `eglCreateWindowSurface failed, reporting an error of EGL_SUCCESS`, as did the guest-free x86 `re2dj_opengl_post_shader_probe`; pinning the EGL vendor, Mesa passed and NVIDIA failed, and pinning the external platform, `egl-wayland` (v1) passed 12/12 while `egl-wayland2` failed; x64 passes with the same NVIDIA setup, and the 32-bit NVIDIA libraries (`libnvidia-gl-595:i386`, `libnvidia-egl-wayland1:i386`) were installed. The guide gives the workaround. Documents: the design and work order, the kb topic and its index, the guide's NVIDIA section in both languages and the ARCHITECTURE paragraph on the Linux x86 bridge.*

- **검증**(Ubuntu 26.04, GCC 15.2, RTX 4090)
  - `linux-x86-debug` + `RE2DJ_WARNINGS_AS_ERRORS=ON`: 전체 빌드 성공(경고 없음), CTest 5개 통과. `nm`에 `B g_native_host_gs_selector`.
  - x86 GL probe `post_shader`: X11 12/12, Wayland(`egl-wayland` v1 지정) 12/12, Mesa 벤더 지정 12/12.
  - x86 Debug 실행(Wayland, v1 지정): 4th `--post-shader crt`는 25초에 API 호출 246,426회 뒤 `host window closed`. 6th `--post-shader=scanline -- ez2dj6th`는 런처·`EZ2DJ6TH.EXE` 자식이 scanline을 적용했고, 45초에 자식이 창 닫힘으로, 런처가 `ExitProcess(0x00000000)`로 끝났다. X11에서 4th는 20초에 105,778회 뒤 정상 종료.
  - `linux-x86-release`: 빌드 성공(경고 없음), ELF 32-bit i386, NEEDED `libm.so.6 libc.so.6 ld-linux.so.2`. 4th 실행 중 uinput 가상 패드 연결·분리가 `added`·`removed`로 기록되고 정상 종료.
  - x64: 두 파일은 x64에서 컴파일되지 않는다. x64 Debug·Release와 clang 빌드는 [작업 460](20261005-460-spdlog-fmt-clang21.md)에서 다시 빌드했다.
  - **하지 못한 것**: CI의 x86 컨테이너(GCC 12)와 Windows x86. push 뒤 CI에서 확인한다. Windows x86 backend는 이 파일을 쓰지 않는다.

  *Verification (Ubuntu 26.04, GCC 15.2, RTX 4090): `linux-x86-debug` with `RE2DJ_WARNINGS_AS_ERRORS=ON` builds in full with no warnings and passes 5 CTest tests, `nm` showing `B g_native_host_gs_selector`; the x86 `post_shader` GL probe passes 12/12 under X11, under Wayland with `egl-wayland` v1 pinned and with the Mesa vendor pinned; x86 Debug on Wayland with v1 pinned runs 4th with `--post-shader crt` for 25 s (246,426 API calls) to `host window closed`, and 6th with `--post-shader=scanline -- ez2dj6th` applies scanline in the launcher and the `EZ2DJ6TH.EXE` child, which ends on its window closing at 45 s with the launcher at `ExitProcess(0x00000000)`; under X11 4th ends cleanly after 105,778 calls in 20 s; `linux-x86-release` builds with no warnings as an ELF 32-bit i386 executable with NEEDED `libm.so.6 libc.so.6 ld-linux.so.2`, and logs a uinput virtual pad's `added` and `removed` during a 4th run that ends cleanly. x64 does not compile the two files; the x64 Debug and Release and clang builds were rebuilt in [task 460](20261005-460-spdlog-fmt-clang21.md). Not done: CI's x86 container (GCC 12) and Windows x86, to be seen in CI after the push; the Windows x86 backend does not use these files.*
