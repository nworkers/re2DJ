# 작업 445 작업 로그 — Windows host 게임패드 입력 / Task 445 work log — gamepad input on the Windows host

## 2026-10-04

- **reader**: `Sdl3GamepadReader::Update()`(`SDL_UpdateGamepads` 뒤 `SDL_PeepEvents`로 joystick·gamepad 이벤트 범위만 꺼내 ADDED·REMOVED를 처리하고 나머지는 버림)와 `SetDeviceObserver`. `HandleEvent`와 `Update` 모두 observer를 부른다.
- **Windows 입력 클래스**: `Ez2DjKeyboardInput`·`Ez2DancerKeyboardInput`이 `ReadIoConfigText`(새 공통 헬퍼, `std::ifstream`)로 INI 본문을 읽고 `LoadEz2DjIoBindings`·`LoadEz2DancerIoBindings`로 푼다. 멤버는 `Ez2DjIoBindings`·`Ez2DancerIoBindings` 하나씩. `Poll`이 `GamepadControls`를 받아 항목마다 키 또는 패드 컨트롤로 눌림을 본다. 접근자 `button_gamepad`·`turntable_gamepad`. `keyboard_input_common`의 `ReadKeyboardKeyBinding`(`GetPrivateProfileStringA`)은 지웠다.
- **주입 런타임**: `g_gamepad_reader`(해제하지 않는 포인터; DllMain에서 SDL 스레드를 내리지 않기 위해), `g_gamepad_controls`, `g_gamepad_refresh_tick`. 키보드 입력이 초기화되는 첫 포트 read에서 reader를 초기화하고 observer로 `re2dj:gamepad:added/removed name=...`을 런타임 로그에 남긴다. 실패하면 `re2dj:gamepad:unavailable`을 남기고 키보드만 쓴다. VFS trace의 `io-config` 줄에 `gamepads=N`. 매 read에서 `GetTickCount64()`가 바뀐 경우에만 `Update`·`Read`.
- **CMake**: 주입 런타임에 `src/input/gamepad.cpp`, `io_bindings.cpp`, `sdl3_gamepad_reader.cpp`. 두 키보드 입력 테스트에 `RE2DJ_TEST_SOURCE_DIR`.
- **테스트**: `ez2dj_keyboard_input_test`에 게임패드 검사(기본값과 예제 `[gamepad]` 대조, 부분 덮어쓰기, `Y`+`LB`를 쥔 `Poll`이 포트 `0x102`를 보드 테스트와 같은 `0x7d`로 만듦, 모르는 이름 오류), `ez2dancer_keyboard_input_test`에 같은 종류의 검사, `sdl3_gamepad_reader_test`에 펌프 없는 `Update` 경로(둘째 가상 패드의 추가·버튼·트리거·제거, observer 호출, 큐에 남은 이벤트 없음).
- **문서**: README·ARCHITECTURE·Windows 런타임 가이드의 "Windows는 키보드만" 문구 갱신, 작업 444 설계 4절에 후속 표시.

  *The reader gains `Update()` (`SDL_UpdateGamepads`, then only the joystick and gamepad event range through `SDL_PeepEvents`, ADDED and REMOVED handled and the rest dropped) and `SetDeviceObserver`, called from both `HandleEvent` and `Update`. `Ez2DjKeyboardInput` and `Ez2DancerKeyboardInput` read the INI text through the new common helper `ReadIoConfigText` (`std::ifstream`) and resolve it with `LoadEz2DjIoBindings` / `LoadEz2DancerIoBindings`, each holding one `Ez2DjIoBindings` / `Ez2DancerIoBindings`; `Poll` takes `GamepadControls` and holds an entry on its key or its pad control, with accessors `button_gamepad` and `turntable_gamepad`; `ReadKeyboardKeyBinding` (`GetPrivateProfileStringA`) is gone from `keyboard_input_common`. The injected runtime keeps `g_gamepad_reader` (a pointer never freed, so SDL's thread is not torn down from DllMain), `g_gamepad_controls` and `g_gamepad_refresh_tick`, initialises the reader on the first port read where keyboard input is, logs `re2dj:gamepad:added/removed name=...` through the observer, logs `re2dj:gamepad:unavailable` and keeps the keys on a failure, adds `gamepads=N` to the VFS trace's `io-config` line, and `Update`s and `Read`s only when `GetTickCount64()` changed. CMake adds `src/input/gamepad.cpp`, `io_bindings.cpp` and `sdl3_gamepad_reader.cpp` to the injected runtime and `RE2DJ_TEST_SOURCE_DIR` to both keyboard input tests. Tests: gamepad checks in `ez2dj_keyboard_input_test` (defaults against the example `[gamepad]`, partial overrides, a `Poll` holding `Y` and `LB` making port `0x102` the board test's `0x7d`, an unknown-name error), the same kind in `ez2dancer_keyboard_input_test`, and the pump-less `Update` path in `sdl3_gamepad_reader_test` (a second virtual pad's addition, button, trigger and removal, the observer's calls, and no event left in the queue). Documents: the "Windows keyboard only" wording in README, ARCHITECTURE and the Windows runtime guide, and a follow-up note in task 444's section 4.*

    - 두 키보드 입력 테스트는 처음 CTest에서 실패했다. CTest의 작업 디렉터리(build)에서 상대 경로 `config/...example.ini`가 없기 때문인데, 예전에는 `GetPrivateProfileStringA`가 없는 파일을 조용히 "항목 없음"으로 넘겨 **기본값끼리 비교하며 통과하던 것**이었다. 이제 파일 읽기 실패를 보고하므로 드러났다. 테스트가 `RE2DJ_TEST_SOURCE_DIR`로 저장소의 예제를 가리키게 고쳤다.

SDL 조이스틱 스레드와 숨은 창이 원본 프로세스 안에 생겨도 실행에 영향이 없었다.
  - Linux x64 debug(경고를 오류로): build 성공, CTest 5개 통과(`re2dj_sdl3_gamepad_test` 36개 검사).
  - **하지 못한 것**: 패드 버튼이 게임 입력으로 들어가는지는 사람이 눌러야 한다. 포트 비트까지는 단위 테스트가 확인했으므로 reader → `Poll` → 보드 경로는 닫혔고, 남은 것은 사용자가 6th에서 `START`·`BACK`(코인)·`X`~`RB`를 눌러 반응을 보는 것이다.

## 2026-10-04 — 사용자 확인: 버튼이 들어가지 않음 / User check: buttons did not reach the game

- 사용자가 눌러 보니 반응이 없었다. 원인은 SDL joystick의 포커스 규칙이다(설계 3-1): SDL 창이 있고 `SDL_GetKeyboardFocus()`가 없으면 눌림을 버린다. Windows 제품의 SDL 창은 host 창 아래 자식 HWND를 감싼 것이라 키보드 포커스를 가진 적이 없다. 단위 테스트는 SDL 창이 없어 이 규칙을 지나쳤다.
- **수정**: `Sdl3GamepadReader::AllowBackgroundEvents(bool)`(hint `SDL_HINT_JOYSTICK_ALLOW_BACKGROUND_EVENTS`). 주입 런타임이 reader를 만들기 전에 `true`로 켠다. Linux host는 기본값 그대로다.
- **테스트**: `sdl3_gamepad_reader_test`에 숨은 SDL 창(포커스 없음)을 만들고 가상 패드 버튼을 누르는 절을 더했다. 허용 전에는 눌림이 보이지 않고, 허용 뒤에는 보인다. 비디오 드라이버가 없는 host에서는 건너뛴다.
- **검증**: Windows x86 build 성공, `re2dj_sdl3_gamepad_test` 45개 검사 통과(기준 패드 1개, 포커스 절 포함). Linux x64 build 성공, 같은 테스트 45개 검사 통과(WSLg에서 포커스 절 실행), CTest 통과. Xbox 패드를 꽂은 `re2dj.exe ez2dj6th` 20초 실행: 자식 로그에 `gamepads=1`과 `added name=Xbox Series X Controller`, 오류 없음.
- **남은 것**: 버튼이 실제로 게임에 들어가는지 사용자가 다시 확인한다.
