# v0.0.11 다음 세션 작업 인계

## 현재 도달점

이번 병합 범위는 작업 076~080이다. SDL3/OpenGL renderer를 Windows 종속 WGL 구현에서 공용 backend로 옮겼고, Linux x86-64 host/i386 helper가 원본 PE32 entry와 첫 import/fault/exit 경계까지 실행하도록 연결했다. Win32에서는 일반 `re2dj --run`이 기존 진단 launcher와 같은 original-process engine을 사용하며, Windows loader가 보호된 원본 `ez2dj.exe`를 main image로 적재하고 injected runtime이 확인된 Win32·DirectX·I/O 경계를 HLE한다.

사용자는 Win32 제품 명령으로 원본 실행이 된다고 확인했다. 오디오는 출력되지만 지나치게 작다는 관찰에 따라 최종 SDL mix에 독립 master gain을 추가했다. 제품 기본값은 `+6 dB`이고 `--audio-gain-db -24..+18`로 조절할 수 있다. DirectSound buffer별 dB, pan, frequency와 duplicate 상대 상태는 변경하지 않았다.

## 다음 세션의 첫 작업

세션 종료 시 기존 Debug `re2dj.exe`와 `ez2dj.exe`가 실행 중이어서 Debug output이 잠겨 있었다. 먼저 기존 게임을 정상 종료한 뒤 Debug 전체 build를 갱신한다.

```powershell
cmake --build --preset windows-x86-debug --config Debug
ctest --preset windows-x86-debug --output-on-failure
```

그다음 실제 HDD에서 기본 `+6 dB`와 `+12 dB`를 비교한다.

```powershell
.\build\windows-x86\bin\Debug\re2dj.exe --hdd .\roms\ez2dj1stse --target ez2dj1stse --audio-gain-db 6 --run
.\build\windows-x86\bin\Debug\re2dj.exe --hdd .\roms\ez2dj1stse --target ez2dj1stse --audio-gain-db 12 --run
```

확인할 내용은 체감 음량, clipping·왜곡, `title.wav`와 효과음의 상대 음량이다. `+12 dB`에서 왜곡이 있으면 `9`, `6`, `3`, `0` 순서로 낮춘다. 단순 master gain으로 캐비닛 동작을 충분히 재현하지 못하면 추정 구현하지 말고 원본의 일곱 WINMM mixer import 호출 순서, structure, control ID와 값을 먼저 trace한다.

## 이후 Win32 우선순위

1. 로고·Title 장면, 투명도·컬러키·mask와 animation 속도 재검증
2. 키보드와 legacy I/O port 입력으로 메뉴·게임 상태 전이 확인
3. canonical 실행의 guest write가 원본 HDD가 아닌 overlay에만 기록되는지 확인
4. runtime 증거에 따른 WINMM mixer HLE 또는 host audio policy 보정
5. `FindFirstFileA` 계열 directory enumeration과 `GetPrivateProfile*`/`WritePrivateProfileStringA` HLE

Linux 작업 077은 삭제된 것이 아니라 보류된 상태다. 재개할 때는 공용 Win32 import dispatcher와 ABI marshalling부터 이어간다.

## 유지해야 할 결정

- 원본 x86 게임 코드가 항상 주 실행 경로다.
- Win32 제품 경로는 custom PE manual mapping이 아니라 Windows loader의 main-image process를 사용한다.
- 현재 검증된 Win32 제품 target은 `ez2dj1stse`뿐이다.
- 원본 HDD는 읽기 전용이며 쓰기는 `overlays/<target-id>`로 보낸다.
- 원본 자산과 실행 파일은 저장소에 추가하거나 commit하지 않는다.
- 확인되지 않은 WINMM·캐비닛 동작은 확정 사실로 기술하지 않는다.
