- 처음에는 이 환경에 `.gtide` 디렉터리 덤프만 있는 줄 알고, 그 빌드를 위한 프로필 변형과 LPTDI 장치를 설계했다. 그 사이 사용자가 `roms/ez2dj1stse`를 CHD로 바꿨다. 그래서 그 변경은 커밋 전에 모두 되돌리고 CHD 기준으로 설계를 다시 썼다.
  *At first only the `.gtide` directory dump seemed to be here, and a profile variant and an LPTDI device were designed for it. Meanwhile the user replaced `roms/ez2dj1stse` with the CHD, so those changes were all reverted before any commit and the design was rewritten around the CHD.*
- CHD 빌드의 Hardlock 자료가 로컬 `cfg/`에 없었다. 사용자의 reSoftlock 작업 공간에 확정 map(`artifacts/ez2dj1stse/maps/resolved.map`, 후보 74)이 있어 `cfg/hardlock-ez2dj1stse.map`으로 복사했다. `cfg/hardlock.ini`의 `[ez2dj1stse]`에는 작업 224가 1st SE에서도 성립한다고 확인한 3rd·4th의 재생값을 넣었다. `cfg/`는 Git이 무시하며, 값은 이 로그에 적지 않는다.
  *The CHD build's Hardlock material was missing from the local `cfg/`. The user's reSoftlock workspace holds the resolved map (`artifacts/ez2dj1stse/maps/resolved.map`, candidate 74), copied to `cfg/hardlock-ez2dj1stse.map`. The `[ez2dj1stse]` section of `cfg/hardlock.ini` received the 3rd/4th replay values that Task 224 confirmed also hold for 1st SE. `cfg/` is ignored by Git, and no values are written here.*
- Linux x64 빌드는 `/mnt/c` 위의 4코어에서 느려(26분에 575개 중 155개), `re2dj`와 `re2dj_unit_tests`만 빌드하도록 줄였다.
  *The Linux x64 build on `/mnt/c` with four cores was slow (155 of 575 in 26 minutes), so it was narrowed to `re2dj` and `re2dj_unit_tests`.*

  *First run (x64): all 39 Hardlock requests completed (17 transforms `completed`), and it stopped at `GetProcAddress(GDI32, "SetBkColor")` while resolving the original imports. Of the 144 original `.idata` imports, this was the only one missing from the facade.*
