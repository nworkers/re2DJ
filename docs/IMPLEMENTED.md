# 구현 완료 항목 / Implemented

완료된 구현·검증 항목을 누적 기록합니다. 상세 근거는 각 작업 로그와 설계 문서를 참조합니다.

*This document records completed implementation and verification items. Detailed evidence remains in the corresponding design and work-log documents.*

- **작업 141 — Hardlock 코드를 HLE 계층으로 정리하고 성격을 정의했습니다.** 흉내 코드가 `include/re2dj/hle/hardlock/`와 `src/hle/hardlock/`, namespace `re2dj::hle::hardlock`으로 이동했고 계층 표에 행이 생겼습니다. 계약을 알아내려고 만든 진단(XOR 인과 probe, challenge 기록, descriptor ID 기록, protocol tracker와 그 trace, 전용 descriptor probe)을 제거했습니다. 어떤 코드도 소비하지 않던 seed·module address 비밀 경로 전체와 `--hardlock-config`, `hardlock_secret_config_required`, ini의 `modad`/`seed1..3`도 함께 제거해 설정에는 re2DJ가 실제로 쓰는 값만 남습니다. `HardlockStubDevice`를 `HardlockDevice`로 바꿨습니다. 이 계층은 **네 IOCTL에 규격대로 답하는 장치 경계이며 암호 연산을 하지 않습니다.** 응답 값은 저장소 밖에서 계산하고, 고정된 challenge 집합 덕분에 오프라인 표 하나로 성립합니다. 두 제품 실행이 통과 지문을 그대로 재현했습니다. 근거: [설계](design/20260902-141-hardlock-hle-consolidation.md), [작업 지시](work-orders/20260902-141-hardlock-hle-consolidation.md), [작업 로그](work-logs/20260902-141-hardlock-hle-consolidation.md).

  *Task 141 — consolidated the Hardlock code into the HLE layer and defined its character. The emulation moved to `include/re2dj/hle/hardlock/` and `src/hle/hardlock/` under `re2dj::hle::hardlock`, with a layer-table row. The contract-discovery diagnostics were removed — the XOR causality probe, challenge recorder, descriptor ID recorder, protocol tracker with its traces, and the dedicated descriptor probe — along with the entire seed and module-address path no code consumed, `--hardlock-config`, `hardlock_secret_config_required`, and the ini's `modad` and `seed1..3`, so the configuration now holds only values re2DJ uses. `HardlockStubDevice` became `HardlockDevice`. The layer is **a device boundary answering four IOCTLs to specification, performing no cryptography**: values are computed outside the repository, and one offline table suffices because the challenge set is fixed. Both product runs reproduced the passing fingerprint.*

- **작업 140 — 판별된 Hardlock 재료를 제품 실행 경로로 승격했습니다.** `re2dj ez2dj3rd`와 `re2dj ez2dj4th --run`이 옵션 없이 보호를 통과합니다. 세 재료(`cfg/hardlock-<profile>.map`, ini의 `response450`·`tail44c`)를 profile 기본값으로 읽으며, 값은 코드가 아니라 사용자의 Git-ignore된 `cfg/`에서만 옵니다. 매핑이 없으면 replay도 적용하지 않는 전부-또는-전무 규칙입니다. 3rd profile의 `hle_dynamic_vfs`와 `hle_wts_active_console`을 켰습니다. 근거: [설계](design/20260902-140-hardlock-cfg-material-defaults.md), [작업 지시](work-orders/20260902-140-hardlock-cfg-material-defaults.md), [작업 로그](work-logs/20260902-140-hardlock-cfg-material-defaults.md).

  *Task 140 — promoted the identified Hardlock material to the product execution path, so `re2dj ez2dj3rd` and `re2dj ez2dj4th --run` pass the protection with no options. A profile default reads the map file and the optional `response450` and `tail44c` keys, all supplied from the user's Git-ignored `cfg/` rather than code, applied all-or-nothing. The 3rd profile gained `hle_dynamic_vfs` and `hle_wts_active_console`.*

- **작업 139 — 두 제품의 보호 통과 응답 집합을 판별했습니다.** 외부 생성기의 후보를 전부 주입해(3rd 105개, 4th 93개) 제품마다 정확히 하나가 다른 실행 형태를 보임을 확인했습니다. 나머지는 transform loop 직후 fault이고, 판별된 후보만 종료 코드 `0x00000000`으로 끝나며 장치를 다시 열고 `EZ2DJ.ini`를 읽습니다. 복호화된 게임 코드의 동작입니다. 각각 3회 재현했고 fault 주소는 판별에 쓰지 않았습니다. 그 seed가 물리 dongle 값과 같다는 것은 추정입니다. 근거: [작업 지시](work-orders/20260902-139-hardlock-candidate-judgement.md), [작업 로그](work-logs/20260902-139-hardlock-candidate-judgement.md).

  *Task 139 — identified the response set that passes the protection for both products. Injecting every external-generator candidate — 105 for 3rd and 93 for 4th — left exactly one per product with a different run shape: the rest fault right after the transform loop, while the identified candidate exits `0x00000000`, reopens the device, and reads `EZ2DJ.ini`, which is decrypted game-code behavior. Each reproduced three times, judged by run shape rather than the fault address; that its seeds equal the physical dongle's is inferred.*

- **작업 138 — ez2dj3rd의 transform challenge 목록을 32개로 확정했습니다.** 기록된 18개는 3rd 고유 규칙이 아니라 `.text` 도중에 끊긴 관찰의 하한이었습니다. 4th와 같은 전 section 규칙이며, 원본 실행 파일에서 유도한 32개가 관찰 목록을 값과 순서까지 재현했습니다. 3rd가 `GetProcAddress`로 해석한 `CreateFileA`로 장치를 여는 사실과, resolver가 꺼져 있으면 보호가 대화상자 뒤 종료 코드 `0x00000009`로 끝난다는 사실을 확인하고 launcher 진단 flag `--hle-dynamic-vfs`를 추가했습니다. 근거: [설계](design/20260902-138-ez2dj3rd-transform-challenge-observation.md), [작업 로그](work-logs/20260902-138-ez2dj3rd-transform-challenge-observation.md).

  *Task 138 — established ez2dj3rd's transform challenge list as 32 entries. The recorded 18 was the lower bound of an observation cut short inside `.text`, not a rule specific to 3rd: the same all-section rule as 4th derives 32 challenges from the original executable, matching the observed list in value and order. The task also confirmed that 3rd opens its device through a `GetProcAddress`-resolved `CreateFileA` and that without the dynamic resolver the protection ends at a dialog with exit code `0x00000009`, and added the `--hle-dynamic-vfs` launcher diagnostic.*

- **작업 137 — 복호화 영역 판별기를 추가했습니다.** 플랫폼 중립 `ScoreCodeRegion`이 바이트 span에서 Shannon 엔트로피, `55 8b ec` prologue 수, `cc` padding run 수, zero byte 비율을 계산해 `ciphertext-like` / `code-like` / `indeterminate` 3상태로 보고하고, `re2dj_code_score`가 파일·HDD·CHD 입력을 섹션 또는 청크 단위로 채점합니다. 원본 4th 섹션 점수가 분석 문서 기록값을 재현했고, `.protect` 첫 1 KiB가 평문 코드임을 새로 확인했습니다. 근거: [설계](design/20260902-137-decrypted-region-judge.md), [작업 지시](work-orders/20260902-137-decrypted-region-judge.md), [작업 로그](work-logs/20260902-137-decrypted-region-judge.md).

  *Task 137 — added the decrypted-region judge. The platform-neutral `ScoreCodeRegion` computes Shannon entropy, `55 8b ec` prologue count, `cc` padding runs, and zero-byte share from a byte span and reports `ciphertext-like`, `code-like`, or `indeterminate`, while `re2dj_code_score` scores file, HDD, and CHD inputs by section or chunk. The original 4th section scores reproduced the analysis record, and the first 1 KiB of `.protect` was newly confirmed as plaintext code.*

- **작업 128 — 공식 Hardlock driver 정적 계약 확인 완료.** `haspnt64` release가 안내한 Thales 8.31 installer를 실행하지 않고 임시 디렉터리에서만 분리해 유효하게 서명된 Gemalto x86 3.92/x64 3.93 `hardlock.sys`를 확인했습니다. x64 driver의 직접 dispatch는 4th에서 관찰한 네 IOCTL을 모두 포함하며 `0x450` 6바이트, `0x44c` 256바이트, `0x458` equal-size 256바이트 이상 및 block-count별 8바이트 payload 계약을 독립적으로 확인합니다. Function `0x0e`는 내부 device transport로 넘어가며 host-side 세-seed 변환은 확인되지 않아 transform 구현은 계속 TODO입니다. 다운로드 binary와 raw disassembly, 실제 key material은 저장소에 포함하지 않았습니다. 근거: [설계](design/20260901-128-hardlock-vendor-driver-static-analysis.md), [분석](analysis/ez2dj4th-hardlock-runtime.md), [작업 로그](work-logs/20260901-128-hardlock-vendor-driver-static-analysis.md).

  *Task 128 — official Hardlock driver static contract verification complete. The Thales 8.31 installer referenced by the `haspnt64` release was never executed and was unpacked only in a temporary directory, yielding validly signed Gemalto x86 3.92/x64 3.93 `hardlock.sys` drivers. Direct x64 dispatch independently confirms all four IOCTLs observed from 4th: six bytes for `0x450`, 256 bytes for `0x44c`, and equal input/output sizes of at least 256 bytes with eight-byte payload units per block count for `0x458`. Function `0x0e` continues through internal device transport; no host-side three-seed transform was identified, so implementation remains in TODO. No downloaded binary, raw disassembly, or real key material entered the repository. Evidence: [design](design/20260901-128-hardlock-vendor-driver-static-analysis.md), [analysis](analysis/ez2dj4th-hardlock-runtime.md), and [work log](work-logs/20260901-128-hardlock-vendor-driver-static-analysis.md).*
